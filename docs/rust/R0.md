# R0 — исходные измерения и совместимость

Начат 10.11.2026. План: [19-PLAN-rust-migration.md](../19-PLAN-rust-migration.md).
Этот документ — начальная карта, не заявление о полном паритете Rust и TypeScript.

## Воспроизводимые измерения

```sh
npm ci
npm run build
node scripts/rust-baseline.mjs --out /tmp/pult-r0-evidence/baseline.json
```

Скрипт создаёт отдельный процесс настоящего TypeScript-демона с временным home/socket и штатным
RPC-клиентом. Платные модели и установленный Пульт не используются. Три сценария: 0, 1 и 10 активных
тредов fake Codex; треды делят один app-server, как в продукте. На каждом стенде — истории из 100 и
10 000 синтетических событий. Фиксируются запуск Node + импортов + демона до подключения, p50/p95 RPC, первый и повторный
запрос страницы, RSS демона и дерева процессов, CPU простоя, ОС/CPU/Node/commit/hash скрипта.

RSS включает импортированные test helpers, но измеряется в отдельном процессе без драйвера RPC.
Это fixture baseline, не production benchmark: он не измеряет скорость модели, реальные CLI,
Electron, GPU или мобильные драйверы. Для выводов о выигрыше Rust нужна одинаковая нагрузка
с теми же гарантиями сохранения. Повторить после слияния пользовательских PR и отдельно измерить окно.
Один прогон при параллельных сборках не доказывает отсутствие регрессии; перед сравнением выполнить
минимум три последовательных прогона без других сборок и сравнить распределения.

`src/adapters/types.ts` и маршруты `src/daemon/server.ts`. Ниже команда снимает список буквальных
RPC-case из исходника; динамические регистрации и семантику нужно сверять вручную.

```sh
node scripts/rust-contract-inventory.mjs --out /tmp/pult-r0-evidence/contracts.json
```

Нормализация при сравнении двух runtime может исключать timestamp, pid и временные пути,
но не порядок событий, request/turn/session ID, права, исход ошибки и подтверждение сохранения.
Старый баг разрешено исправить отдельным решением; не воспроизводить его ради совпадения трасс.

## Статус начала

- `in progress`: baseline демона и начальная карта сценариев.
- `not run`: полный пользовательский e2e на итоговом main, real-provider baseline, окно, CPU/GPU окна.
- `not implemented`: общий исполнитель контрактных сценариев против двух демонов; Rust-паритет.
- Следующая контрольная точка: повторные baseline на объединённом main и привязка каждой строки карты
  к фактическим результатам. R1 не зависит от наличия полного product parity, но R2 требует завершения R0.

## Обновлённые измерения объединённого кода

Повторены три прогона демона на Node 24.21.0 без параллельных сборок. Данные находятся
в `spike/rust/evidence/node24-daemon-{1,2,3}.json`. Новый скрипт
`scripts/rust-window-baseline.mjs` собирает метрики изолированного окна через штатный e2e harness.
Для запуска нужны сборки root и shell, скрипт сам собирает отдельный модуль harness перед замером.

```sh
npm ci && npm run build
cd shell && npm ci && node scripts/build.mjs --tests && cd ..
node scripts/rust-window-baseline.mjs --out /tmp/unused-window-baseline.json
```

Результат окна сохранён в `spike/rust/evidence/window-node24.json`. Суммарный RSS измерен
через ps для Electron, демона и их потомков. CPU отражает интервальную оценку Electron,
полный CPU дерева и GPU timing требуют дальнейшего измерения. Запуск окна включает
подготовку fixture harness и подключение, сборка самого harness выполнена до начала таймера.
