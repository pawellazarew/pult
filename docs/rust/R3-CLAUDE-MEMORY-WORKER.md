# Claude Worker: scoped memory catalog data

Этот шаг — Worker consumer, не daemon memory wiring и не warm-process parity. `ScopedMcp` получает совместимые default-методы `catalog(Ticket,generation) -> Task<Result<Option<String>,WorkerError>>` (None) и `check(&Ticket,generation) -> bool` (true). Старые реализации сохраняют поведение. MCP preparation/context/credential ABI не меняется.

После owned MCP prepare Worker получает catalog для exact Ticket/generation. Для обычного input он кодируется отдельным native text data block после attachment blocks и перед runtime context. User text, `message.user`, provider system instructions, argv и MCP credentials не изменяются. Catalog остаётся в private native stdin; Worker не добавляет его в журнал или ошибки. Trusted catalog producer отвечает за содержимое; Worker не обещает произвольный String secret-free. Catalog size ограничен native input budget; итоговый frame сохраняет существующий предел 36 MiB.

Node source: `src/adapters/claude/argv.ts:isSlashCommandTurn` и `adapter.ts` около1183 документируют измеренный контракт: slash-команда без вложений требует один текстовый блок, иначе `/context`/`/compact` становятся обычным model text. В текущем Node adapter нет memory-catalog insertion. Worker сохраняет этот контракт: **не запрашивает** и не вставляет catalog для существующего `is_slash_command_turn`; scope всё равно prepared и проверяется. Slash с вложениями остаётся ordinary input.

После blocking encoding свежий `ScopedMcp.check` выполняется в том же blocking шаге, что final DispatchGate, cancel CAS и first stdin poll, без await между ними. Callback обязан быть ограниченной in-memory проверкой. Panic или false запрещает input; реальный Process остаётся в private vault до stop/join. Catalog constructor/future panic тоже fail-closed; cleanup по-прежнему owns MCP resources до известного завершения. Cancel не бросает encoding/catalog IO; существующий Driver cleanup/quarantine контракт сохраняется.

Сохранена текущая граница `Config.broker`: при false MCP не подготавливается, catalog не запрашивается. Текущий `claude_runtime.rs` создаёт Worker с `broker:true` для всех access modes, поэтому production composition готовит Factory. Будущий standalone memory без broker потребует отдельного контракта; default hook не добавляет скрытое право.

Focused tests используют настоящий holder и синтетический Python Claude: standalone data blocks и оригинальный user receipt; отсутствие synthetic private key в stdin/journal; slash shape и scope check; отдельные attachment/catalog/runtime blocks; revoke во время детерминированно удерживаемого blocking encoder; synchronous catalog/check panic и cleanup без input. Encoder hook существует только под cfg(test), без production environment fault switches. Это проверка протокольной формы/владения, не live qualification установленного Claude или модели. Autoallow native MCP tool rules не добавляются; реальный permission/read UX CLI требует отдельной квалификации.
