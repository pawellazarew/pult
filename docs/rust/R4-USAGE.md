# R4: daemon-epoch usage

Rust owner RPC `usage.get` and preview CLI `usage [--json]` report all registry sessions, in registry order, including archived/untouched sessions. Restart resets totals, even when durable history contains usage events. This is the behavior of the current Node manager.

Each manager-owned `usage.updated` result increments turns once and adds normalized input/output/cache-read tokens using binary64 arithmetic. A supplied numeric totalCostUsd replaces cost; it is not summed. Rate-limit updates replace only status/windows/resetsAt, retaining opaque nested values and missing-versus-null distinctions. First-row provider comes from the registry, defaulting to claude for unknown names. Such hidden rows can become visible on later create. Separate committed result events are counted separately, including parent events and ZCode's two result envelopes when both are emitted.

Only `runtime_journal::HostSink.append` updates the optional projection, after known successful global commit and before commit publication. Debug `events.emit`, direct EventStore appends, historic events and status projection do not update it. Session projection-file degradation does not undo a successful global commit. Actual journal/storage failures retain existing runtime failure handling.

The host bounds are 65,536 distinct accumulated names and 16 MiB retained logical name/provider/rate-limit bytes. There is no eviction or history replay. A capacity/parse failure is prepared before append, then latches usage unavailable **only after confirmed commit**. It never rejects the event, disables execution or marks storage failed. Subsequent usage reads return `unavailable` until restart; partial/zero replacement totals are not served. The normalized numeric/null token inputs of the three existing provider mappers are supported. Malformed internal string/object/boolean token values give explicit usage unavailability rather than JS's unbounded coercion behavior.

Reads admit at most four blocking jobs globally with no queued semaphore waiters. The permit, State Arc and host-job guard live inside the owned job through caller cancellation. Reads take store → registry → usage locks, scan only current registry/cache and enforce response bytes while rendering. No provider/runtime initialization, account discovery, journal scan or disk-history read is needed. Additional reads or overlarge responses return `capacity`. Scoped memory/turn/ask/runtime credentials cannot access usage; unknown object params are ignored.

Text CLI output retains Node RU/EN templates, UTF-16 padding, JS number coercion, exact binary64 `toFixed(4)` rounding and JS percent rounding. JSON emits the entire result in one line, retaining opaque UTF-16 data. The existing bounded JS display helpers are shared with agent CLI without changing their behavior. Server errors follow Node usage's top-level `pult:` prefix and exit 2 only for timeout (other RPC errors exit 1). Preview still requires an explicit scratch home and a running daemon; installed launcher/autostart and production cutover are separate work.

## Evidence

- `scripts/usage-node-oracle.mjs` invokes actual Node createManager + Registry + Store in a temporary home without providers. Its 21-action baseline is `test/fixtures/usage/manager.json`; a Rust integration test reruns it and compares bytes. Rust pure cache compares every snapshot, including unknown-name provider defaults, archive, parent/repeated result, ignored fields, cost replacement, rate-limit opaque UTF-16, direct append bypass, overflow and restart. Remove/recreate in that pure test simulates cache removal only; it is not public Rust rm acceptance.
- `usage_api` tests exercise the real State execution sink and reader: manager-only counting, committed malformed/capacity events leaving execution available, cancelled read admission/ownership, binary64 -0/overflow JSON and opaque rate limits, degraded per-session files and unsuccessful append preparation. Parser tests cover ignored surrogate-containing params and malformed RPC params.
- `rust/tests/cli-usage-oracle.mjs` compares actual public Node CLI and Rust executable stdout/stderr/exit codes strictly on 64 pairs (RU/EN, text/JSON, rounding/coercion/opaque values and errors), including 128 deterministic binary64 rounding samples. The mock uses actual JSON.stringify wire semantics, including -0 → 0. The five additional UTF-16-key cases cover top-level, row, rateLimit, windows and individual windows (five_hour/seven_day), in text and JSON. Selective access delegates to the existing lossless core raw_field reader; unrelated lone-surrogate keys cannot erase known utilization or reject the whole result. The existing agent CLI's 80-pair oracle remains a regression check.
- Existing TypeScript-client foundation interoperability reads usage with opaque ignored params and checks that native runtime remains uninitialized. Existing scope interoperability checks reject usage.

Public Rust `agent.rm` is not implemented in this slice. Its future confirmed-remove path must clear the name's epoch entry under store serialization only after successful registry removal; archive, generic session.ended and create must not clear it. No unused host helper is added. Full rm lifecycle, real installed provider CLI, account/model behavior, launcher service changes and full R4/R5 acceptance remain separate.
