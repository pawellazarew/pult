## Wire and public API

`APP_SERVER_ARGV` is exactly `app-server`, `--stdio`. `agent-server` is an upstream alias; this profile emits only the pinned entry point. There is no prompt, key, model, invented config flag, Codex initialize, or `jsonrpc` member in argv or frames.

`OutboundRequest::{create,resume,subscribe,set_mode,send,close}` builds only explicit supported requests. IDs are bounded canonical strings or JS-safe integers. Host identifiers reject surrounding whitespace because native nonEmptyString trims it; custom session IDs remain supported without an invented sess_ prefix requirement. MCP name __proto__ is rejected because the pinned native adapter uses a normal JS map object. `Workspace` requires an absolute path and an explicit workspaceKey; this module does not derive an identity or read filesystem configuration. Create/resume require an explicitly nonempty stdio MCP list; all servers have `name/command/cwd/args/env/isolation:"session"`. Env is an array of `{name,value}`, never an object. Optional `protocolVersion` and `timeoutMs` have typed builders. Credentials may exist only in the explicit private helper-env serialized in this request, never global env/argv. Types carrying private data have no Debug. Create explicitly sets titleGenerationEnabled:false and supports with_mode(SessionMode); the exact native enum is plan/build/edit/yolo/guarded/auto. set_mode emits session/setMode with optional expectedRevision. Resume derives persisted mode upstream, so the future worker must apply its explicitly captured desired mode before current input; this pure enum/builder grants no host approval. Native startup/hooks/plugins/automation are not disabled by these options.

`decode_frame` consumes exactly one LF or CRLF terminated NDJSON frame; transport must itself bound read buffers before calling it. It rejects raw embedded newlines, Content-Length framing, duplicate keys at all depths, mixed request/result/error envelopes, unknown envelope members, malformed IDs, oversized data and trailing JSON. Errors contain only static messages, never parser text or peer values. Valid JSON blobs in upstream `unknown` fields remain bounded untrusted data. Unknown methods and unsupported event payload fields fail closed. Exact pinned optional trace (traceId/parentId/spanId/traceparent strings, host-capped at 256 bytes each) is validated but never trusted as authorization or request correlation.

Default inbound budget matches the existing `Framing::codex`/`Framing::claude` 16 MiB frame capacity (`worker_process.rs`): 16 MiB including terminator, depth 64, 1,000,000 JSON values, 16 MiB per individual string and 256 bytes per object key. Thus a valid individual opaque history string is not rejected by a hidden 2 MiB sublimit. `DecodeLimits` allows the future dedicated worker or tests to explicitly select smaller budgets; these same defaults are the hard ceilings. All ceilings are resource limits, not upstream schema limits; capacity failure is distinct from malformed JSON. Failure never truncates. Outbound/config bounds remain conservative: 8 MCP servers, 64 KiB combined MCP JSON, 64 arguments/server, 32 env entries/server, 16 KiB/env value, 4 KiB/argument, 128 KiB content and a 256 KiB encoded request frame. These outbound bounds are the Pult host profile, not native upstream limits; upstream content is an unconstrained string. Raw content capacity exceeds the existing Route A 65,536-byte content/context cap, but JSON escaping can exceed the independent wire cap even below that raw cap; encode then returns FrameTooLarge without truncation. The module neither accumulates stream history nor retries sends.

## Acknowledgement and authority boundaries

`Response` retains bounded result data without Debug. Context-specific consuming methods require the pending request ID. `send_ack` additionally requires the expected SID and validates the exact `{sessionId,accepted:true,stateRevision}` shape. This acknowledges input acceptance only; it is not Started. error_code(expected_rpc_id) requires exact request correlation before exposing a bounded native code; it never exposes message/data. The future pending-request map must also bind the request method. In particular -32004 is shared unavailability, not a no-execution or unique missing-session proof.

`snapshot_ack` requires pending request ID, expected SID and the caller's pending `SnapshotMethod::{Create,Resume,SetMode}`. It extracts:

- `protocol.name == "ZCode Protocol"`, `protocol.version == 1`;
- `session.sessionId`, typed `session.mode`, `session.workspace.workspacePath`, `session.workspace.workspaceKey`;
- `projection.sessionId`, which must match session SID;
- `runtime.stateRevision`, `runtime.eventSeq`, optional `runtime.activeTurnId`.

The snapshot root required members are protocol/session/settings/projection/runtime/messages; optional root members are goalStats/todos/todoGroups/slashCommands. Session identity and runtime header member sets are pinned and reject unknown members; their required enums, strings, timestamps, pending request IDs and revision counters are checked. Optional consumed runtime fields are deliveryKind and activeTurnKind. Optional session directorySessionId/parentSessionId/traceId/titleSource are checked. No root revision or fabricated root session ID is assumed.

Settings, projection details, message bodies, model/target and other nested projection data are retained bounded and opaque, not fully schema validated. `untrusted_snapshot()` is an explicitly untrusted future parser input. This profile is NOT a complete snapshot-schema implementation; retaining opaque data does not establish provider/model/config validity or authority. A create/resume snapshot is not input acceptance and cannot mint Started. The future Owner/Worker must compare workspace identity to its own ticket, not trust the returned workspace for authorization.

`TurnStartedCandidate` parses only the supported `session/event` / `turn.started` subset. It retains SID, optional TID, optional inputId/queryId and event sequence. Missing TID/inputId remain absent. A future Actor must match SID/TID and its own host-issued inputId before accepting evidence; neither this type, prompt equality, queryId alone nor sequence alone is Driver authority. Supported additional scalar turn payload fields are explicitly enumerated in the code. Native intent and originMeta objects, arrays of attachment objects, and exact pinned inputSource enum values are validated as bounded untrusted metadata; native ordinary legacy send actually adds intent to turn.started, so it must not be rejected. workflowLaunch remains an explicitly unsupported nested profile until its own exact schema is implemented. Future integration must explicitly extend its event profile before claiming full stream compatibility.

`subscribe` emits session/subscribe with an explicit typed deliveryKind, includeSnapshot:false and optional afterSeq. Native legacy live events require this subscription before send: create/resume alone do not set record.deliveryKind. subscribe_ack checks RPC ID, expected SID, eventSeq and bounded event-envelope shapes; replayed event SIDs must match. Replayed payloads and optional snapshot remain untrusted partial projections. They must be individually parsed and correlated before any future Actor uses them.

Recognized notifications are a separate Incoming::Notification(BoundedNotification), with private data and no Debug. The profile supports exact state.updated root fields and startup/pluginsDegraded reason:timeout, plus exact known session/event type/envelope headers. Non-Started event payload objects are retained opaque and explicitly untrusted, not fully payload-schema validated. Future transport may dispatch/ignore benign observational notifications without treating them as protocol-fatal; terminal/tool/permission state still needs its own future typed consumers. A request carrying an id cannot enter this notification path. Unknown notification methods/types and unknown envelope fields fail closed. Other pinned upstream process/storage/v4 notifications remain unsupported until explicitly profiled; this is not a claim that a future Worker is fully stream compatible.

`close_ack` validates only `{closed?:boolean}`. It establishes neither OS process exit nor cleanup, and this module has no process handle.

## Reverse requests

The profile validates exact bounded params for `session/requestRuntimePreferences`, `interaction/requestPermission`, and `interaction/requestUserInput`. Permission options and nested proposed permission updates are validated but never granted. Unknown fields, duplicate option IDs, empty required choices, invalid origins and malformed known fields fail closed.

`ReverseRequest::default_deny()` emits a response with the incoming RPC ID, never an ID invented from tool input:

- Runtime preferences: disables native search, tool search, app control, subagent runtime config, memory and automatic user-question resolution; emits the pinned `preflight-v1` strategy. It reads no account, model or owner setting.
- Permissions: `{decision:"deny",reason:"Host approval is unavailable"}`; never echoes proposed persistent rules or modified input.
- Questions: `{action:"cancel",reason:"Host input is unavailable"}`.

A future transport handles unsupported/malformed reverse requests with its own static protocol-error policy. A JSON request's session/origin/model/permission fields never authorize host operations.

## Required future integration work

MCP `[]` upstream falls back to global config; it does not disable servers. Nonempty custom MCP still merges plugin/reserved builtin servers. Active session/resume returns an old runtime and ignores replacement MCP configuration, so a future Route B worker needs its own fresh dedicated process and Ticket plus cold resume. This module cannot verify coldness. Route A has no supported private mcp-config/env override; no global/user/workspace config mutation is introduced.

OS spawn and create contain no prompt. `session/send` is the future durable input frontier; an unknown send outcome must never be automatically replayed. Future worker/Actor/Driver integration, full event profile, reverse-request ownership/deadlines, bounded stream framing, MCP helper ticket revocation, child-process cleanup and genuine live/recorded differential qualification remain separate tasks. No production fallback or capability claim is enabled here. Arbitrary JavaScript strings with lone UTF-16 surrogates remain outside this serde_json::Value profile and are rejected; native-string compatibility is not claimed for that case. Opaque nested snapshot sections must never be interpreted as model/permission/readiness authority.
