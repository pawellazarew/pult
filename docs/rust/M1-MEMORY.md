# M1 — локальное хранилище общей памяти

Первый шаг памяти реализует семь owner-only методов Rust: `memory.add`, `update`, `forget`,
`get`, `list`, `search`, `history`. Это новая функция, а не перенос семи старых команд:
каталог содержит 93 метода, Rust поддерживает 22 — 15 прежних и 7 новых.

Запуск пока в отдельном экспериментальном scratch-home. Инъекция каталога в ходы,
доступ агентов через scoped credentials/MCP, предложения заметок и окно памяти относятся
к M2/M3. В этом шаге автор записи — `owner`: выбранная сессия обозначает источник,
а не доказывает, что запись создал соответствующий провайдер.

## Данные и подтверждение записи

`<home>/memory/memory.sqlite3` — отдельная SQLite-база с FTS5. Нынешние сессии,
конфигурация и NDJSON-журнал сохраняют прежний формат. SQLite поставляется через
`rusqlite` с bundled feature; системная версия SQLite не определяет доступность FTS5.

Каталог memory создаётся с правами 0700, база — 0600. Проверяются тип, владелец,
права, число ссылок, inode каталога/базы и опасные sidecars. Симлинки базы и каталога
отвергаются. Это проверки наблюдаемых путей, не защита от процесса с полными правами
того же пользователя, который намеренно подменяет данные.

SQLite использует DELETE journal и synchronous FULL, ограниченное ожидание блокировки,
application_id PMEM и user_version 1. Неизвестная версия, непустая SQLite-база без маркера Пульта
и повреждённые данные не переинициализируются молча. Ошибка открытия отключает
сервис памяти: `daemon.status.memory` сообщает причину, остальные функции демона
доступны. После исправления данных требуется перезапуск. При занятом mutex статус
памяти сообщает `busy`, не задерживая статус демона.

Добавление/изменение/удаление одной транзакцией сохраняет текущую запись, снимок версии,
поисковый индекс и receipt — сохранённый ответ успешной команды. API отвечает после
commit. Откат до commit не создаёт receipt. Обрыв ответа или ошибка после commit
оставляют клиенту неизвестный исход; повторять нужно тот же commandId после устранения
ошибки. Проверка рестарта и SIGKILL после подтверждения
относится к падению процесса, а не к испытанию отключения питания оборудования.

`commandId` обязателен для изменений. Повтор с теми же параметрами и контекстом возвращает
исходный ответ; другой запрос с этим ID даёт `command_conflict`. Ответ receipt —
подтверждение прежней операции, он может отличаться от текущего `get` после дальнейших
правок. Повтор add после forget не создаёт запись заново. Update/forget требуют
`expectedVersion`; конфликт требует нового чтения и принятия решения о правке.

## Области и идентичность проекта

Owner API принимает необязательный `session` — имя известной сессии в реестре.
Проект определяется по её `worktree.repo` или `cwd`; произвольный `projectId` в запросе
не принимается. У основной папки, подпапок репозитория и linked worktree один проект:
`git:<canonical common git-dir>`. У папки без Git — `dir:<canonical folder>`.

Идентичность определяется чтением ограниченных Git metadata без запуска Git, хуков и
зависимости от переменных GIT_*. Поддержаны обычный, bare, separate-git-dir и стандартный
linked-worktree layout с проверкой обратной ссылки. Metadata ограничены 4096 байтами;
пути должны быть UTF-8. `.git`-симлинки, повреждённые указатели и нестандартный linked
layout возвращают ошибку. Перенос проекта требует будущего явного сопоставления.

Для чтения scope по умолчанию `visible`: текущий проект и global, без сессии — только
global. `scope: project` требует проект. Для **всех изменений** scope по умолчанию project;
global выбирается явно, в том числе при update/forget известного ID. Общая запись может
быть создана без сессии и не требует доступной проектной папки.

Это API владельца. До M2 scope агентов должен определяться их credential-bound сессией,
а проектная идентичность — закрепляться при регистрации контекста; принимать произвольный
selector от агента нельзя. Чтение/запись по настройке выключенной памяти чата и обработка
недоверенного текста в контексте также входят в приёмку M2.

## API и CLI

```sh
pultd-rust --home /absolute/scratch memory add --params '{"scope":"global","commandId":"note-001","name":"build","summary":"Проверка сборки","details":"Запускать проверки перед PR","reason":"Подтверждено владельцем"}'
pultd-rust --home /absolute/scratch memory search --params '{"query":"сборки"}'
pultd-rust --home /absolute/scratch memory list
```

Временный CLI управления принимает `--params` с JSON-объектом и печатает JSON-результат
того же RPC. Удобные флаги и агентские инструменты добавляются в M2; это не подмена
полноценного управления памятью из окна.

- add: commandId, name, summary, details, reason; необязательны scope, session, pinned.
- update: commandId, id, expectedVersion, reason; поля name/summary/details/pinned по выбору.
- forget: commandId, id, expectedVersion, reason; мягкое удаление.
- get/history: id; scope/session, у history также limit/offset.
- list/search: scope/session, limit/offset; search требует query.

Record содержит ID, scope, projectId для проекта, name/summary/details, pinned, version,
createdAt/updatedAt, deleted, author, reason и необязательный sourceSession.
List/search возвращают `{memories, hasMore}` без details; history — `{versions, hasMore}`,
новые версии первыми. Удалённое скрыто из get/list/search, история владельцу доступна.
Полное удаление с очисткой истории, индекса и payload receipts относится к M3.

Лимиты: name 120, summary 500, details 16000, reason 1000 Unicode code points; не более
четырёх байт на code point. Идентификаторы — 1–128 ASCII-букв/цифр и `_.:-`.
Limit: 1–50 (по умолчанию 20), offset: 0–10000. Страницы ограничены 512 KiB, поэтому
следующий offset увеличивается на фактически полученное число записей. Поиск принимает
обычные слова, а не FTS-выражения; берутся первые 16 слов, соединённые AND.

Новые строки памяти должны быть корректным Unicode. Lone surrogate в параметрах даёт
invalid_params с сохранением соединения. Старые lossless API истории не изменены.
Слишком большой полный wire-ответ учитывает ID запроса; при невозможности вместить даже
ошибку с исходным ID сохраняется прежнее ограничение протокола — закрытие соединения.

## Проверка

Storage unit-тесты проверяют конкурирующие подключения SQLite, rollback всех четырёх
частей операции, версии, receipts, scope, FTS, восстановление и опасные пути/форматы.
Отдельные тесты проверяют идентичность Git-проектов.
`rust/tests/memory-interop.mjs` использует настоящий Node-клиент и Rust-демон: wire,
CLI, конфликт двух клиентов, рестарт, изоляция данных, мягкое удаление, неправильные
параметры и повреждённая база без остановки остального демона.

Источники: [rusqlite](https://docs.rs/rusqlite/0.42.0/rusqlite/),
[SQLite synchronous](https://sqlite.org/pragma.html#pragma_synchronous),
[FTS5](https://sqlite.org/fts5.html).
