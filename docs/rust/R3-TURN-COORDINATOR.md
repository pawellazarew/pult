# R3: ядро управления ходом

`turn_snapshot` и `turn_coordinator` — внутренние компоненты Rust-менеджера. Они ещё
не подключены к RPC, State или настоящим адаптерам. `agent.prompt`, `agent.wait`,
исполнение очереди и остановка провайдера остаются unported. Каталог — прежние 27/98.

## Снимок настроек

`TurnSnapshot::try_from(&Record)` копирует имя и createdAt, провайдера, cwd,
model/effort/serviceTier/approval/browser. Изменение реестра после копирования не меняет
этот экземпляр. Неизвестные типы, неподдерживаемые режимы, некорректный Unicode,
относительный cwd и превышение лимитов отвергаются. Отсутствующий approval = ask.
Browser {} и {headed:false} означают headless; null/отсутствие — выключен.

Это снимок **желаемых** настроек, а не разрешение запускать процесс. В частности,
`full`/`inherit` из реестра не доказывают согласие владельца. Будущий driver обязан
до reserve получить эффективный режим через access gate, проверить общую рабочую
папку и владение вложениями, защитить PULT_HOME и учесть holdTurns/removing.
Проверка живого списка моделей, файловой системы и сетевого профиля также не входит
в этот чистый компонент. Вложения пока не перенесены.

Пределы: модель 100 ASCII-байт, effort 16, cwd 4096 UTF-8-байт, createdAt 128 байт.
Грамматика model/effort совпадает с `src/sessions/settings.ts`. Inherit разрешён только
Claude, serviceTier — только Codex. Исходная запись и неизвестные метаданные не меняются.

## Владение ходом

`Coordinator` — синхронная машина состояний. Driver сериализует вызовы и не держит её
mutex во время IO. `reserve` выполняется до первого await, занимает **имя** сессии
и получает собственную копию снимка. Даже другая createdAt не обходит занятую бронь.

Ticket включает случайное поколение экземпляра Coordinator, ключ сессии и монотонный
номер попытки. Старый callback не может изменить новый ход с тем же именем, createdAt
или provider turnId, а также ход нового экземпляра Coordinator. Номер не оборачивается:
после JavaScript-safe максимума новые reserve получают Exhausted.

| Вызов | Предусловие | Результат |
| --- | --- | --- |
| reserve | имя свободно, лимит не исчерпан | Starting, новый ticket |
| dispatch_start | текущий ticket, отмены нет | Dispatching, окончательная копия снимка для отправки |
| provider_started | dispatch выполнен, первый корректный turnId | Running либо CancelProvider при пересечении с отменой |
| request_cancel | текущий ticket | Cancelling; бронь остаётся |
| stopped | текущий отменяемый ticket, driver подтвердил остановку | Interrupted, бронь освобождается |
| start_failed | старт ещё не подтверждён, частичный worker уже закрыт | Failure, бронь освобождается |
| complete | старт подтверждён и foreground-ход завершён | итог адаптера, бронь освобождается |

Повторный cancel идемпотентен. Повторный/старый terminal callback получает Stale и ничего
не меняет. Некорректный текущий переход возвращает ошибку, сохраняя бронь. Таймаут,
отключение клиента и запрос отмены **не являются** подтверждением остановки.
При неизвестном состоянии worker сессия остаётся занятой до выяснения.

`provider_started` означает ответ адаптера, а не durable receipt для человека/очереди.
При позднем start после cancel результат CancelProvider требует остановить именно этот
worker; публиковать его как новую принятую реплику нельзя. Уже готовый неуспешный outcome
нужно обработать до подтверждения queued/question сообщения, как делает Node.

Естественное завершение может пересечь cancel; `complete` сохраняет фактический outcome
и признак cancel_requested. Driver отдельно отвечает за нужное событие interrupted,
закрытие вопросов разрешений, фоновые задачи Claude и возможность следующего запуска.
Завершение foreground-хода не доказывает завершение дерева процессов.

## Ограничения памяти и прав

По умолчанию — 64 активных/отменяемых хода и 128 последних результатов. Конструктор
принимает active 1..4096, finished 0..4096. Переполнение не вытесняет живые ходы;
терминальные результаты вытесняются FIFO. Отсутствие результата в кэше не означает
ошибку или отсутствие durable-истории. Будущий wait использует журнал/собственных
подписчиков, а не гарантирует бессрочное хранение этого кэша.

Ошибка провайдера ограничена code 128 ASCII-байт и message 4096 Unicode code points /
16384 байт. Здесь нет редактирования секретов: будущий driver должен передавать
отредактированный текст перед журналом, логами или публикацией в окно.

До dispatch_start разрешено только явное сужение approval:
full → workspace → ask → read-only. Модель, effort и browser не меняются.
Inherit непрозрачен: разрешено только оставить его без изменений. Переход даже к ask
нельзя считать сужением неизвестной пользовательской политики. Access gate обязан
разрешить эффективную политику до reserve либо отменить текущий запуск и создать новый.
После dispatch_start или запроса отмены снимок менять нельзя. Driver использует
копию из DispatchAction::Proceed непосредственно для IO. Это закрывает окно, когда
команда уже ушла со старыми правами, но ответ провайдера ещё не пришёл. Cancelled/Stale
из dispatch_start запрещает отправку; повторная отправка текущего ticket — ошибка.

## Доказательства и следующий шаг

Unit-тесты проверяют извлечение снимка, ошибки типов, границы, недопустимые переходы,
исчерпание счётчика и нулевое хранение результатов. Интеграционные тесты с управляемым
fake driver используют oneshot-барьеры без sleeps: конкурентная отправка, configure
во время resume, cancel во время старта/исполнения, поздний start, потеря клиента,
переиспользование имени, stale callbacks и лимиты. Эти тесты вызывают настоящий
Coordinator; fake driver не является production-адаптером.

Следующий срез соединяет это ядро с менеджером, durable-журналом и управляемым worker.
Он должен доказать порядок message.user/queue receipts, очистку всех отказов и отмен,
отзыв memory lease, применение consent, защиту папок/вложений, фоновые задачи и
владение процессами. Затем адаптеры Codex → Claude → ZCode и реальные smoke-прогоны.
Полный паритет Node и приёмка R3 этим шагом не объявляются.
