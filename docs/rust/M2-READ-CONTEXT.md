# M2: read-only память доверенной сессии

Этот шаг добавляет безопасный доступ к M1-памяти из отдельного клиента. Исполнение
провайдеров, автоматическое включение каталога в ход и MCP ещё не подключены.
Production-окно продолжает использовать Node; Rust запускается только в scratch-home.

## Регистрация и полномочия

Owner вызывает `memory.context.bind` с `session` и необязательным `enabled` (по умолчанию
true). Сервер берёт существующую неархивную сессию из реестра и закрепляет канонический
проект: `worktree.repo` либо `cwd`. General-сессия получает только global-память.
Клиент не передаёт `projectId`. Изменение `.git` после регистрации не перенаправляет
чтение: новый проект требует явного owner bind.

`memory.context.issue` выдаёт отдельный случайный `mem_`-ключ и публичный контекст.
Повторная выдача отзывает предыдущий ключ этой сессии. Ключ разрешает ровно
`memory.get`, `memory.list`, `memory.search`, `memory.catalog`; history, запись, журнал,
управление демоном и контекстами запрещены. Даже правильный owner token вместе с
полем memory не повышает полномочия. Поля ask/runtime остаются неподдержанными.

Рукопожатие клиента:

```json
{"type":"hello","protocol":1,"memory":"mem_<64 lowercase hex>","client":"memory-cli"}
```

На каждом чтении проверяются отзыв и отпечаток текущей сессии: имя, создание,
провайдер, scope, cwd, worktree и approval. Изменение этих полей требует bind заново.
Заголовок и время просмотра не меняют полномочия. Архивация отзывает регистрацию
и ключи; разархивация их не восстанавливает. Будущие stop/rm обязаны делать тот же отзыв.

`memory.context.revoke` удаляет регистрацию. `memory.context.status` возвращает
контексты без ключей и отпечатков. Публичные поля: session, generation, enabled,
readOnly=true и projectId только для project-контекста. Не более 256 регистраций.
Отключённый контекст виден в status, но не даёт ключ или каталог.

Все регистрации и ключи живут только до перезапуска демона. Bind и revoke аннулируют
также уже открытые соединения при следующем запросе. Чтение, принятое до отзыва,
может завершиться; отзыв не стирает ранее переданное знание. При выдаче ключа
регистрация owner остаётся доступной для owner catalog.

## CLI

Owner-команды используют прежний локальный токен:

```sh
pultd-rust --home /absolute/scratch memory context bind --params '{"session":"chat"}'
pultd-rust --home /absolute/scratch memory context issue --params '{"session":"chat"}'
pultd-rust --home /absolute/scratch memory context status
pultd-rust --home /absolute/scratch memory catalog --params '{"session":"chat"}'
pultd-rust --home /absolute/scratch memory context revoke --params '{"session":"chat"}'
```

Агент получает ключ через `PULT_MEMORY_KEY`, а не аргумент командной строки. При наличии
этой переменной CLI всегда использует узкий транспорт, даже если значение пустое,
невалидное или отозвано. Возврата к owner нет. Клиент не читает содержимое config.json
и run/token. `daemon serve` с этой переменной отказывается запускаться до создания home.
Текст ошибки клиента редактирует случайное отражение ключа сервером.

```sh
# PULT_MEMORY_KEY заранее передаётся окружением запускающего процесса.
pultd-rust --home /absolute/scratch memory catalog
pultd-rust --home /absolute/scratch memory search --params '{"query":"build"}'
```

Scoped-клиент не может выбирать session/projectId; scope разрешает только сузить
закреплённую область. SQL отсекает чужие записи до декодирования, включая lookup по ID.
Внутренние ошибки scoped-чтения не раскрывают пути или содержимое базы.

## Каталог для будущего хода

`memory.catalog` возвращает text, memories=[{id,version}], truncated и context.
В text — заголовок и JSON-строки с id, version, scope, name, summary. Details и reason
не включаются. Сводки считаются недоверенными данными, не дополнительными разрешениями.

Предел text: 4000 Unicode code points и 16000 байт, включая предупреждение об обрезке.
Кандидаты — первые 50 видимых записей в M1-порядке (pinned, затем updatedAt). Если
остались записи или строка не помещается, truncated=true и подсказка search/get.
Ссылки содержат только действительно включённые ID/версии. Следующий запрос видит
сохранённые owner-изменения. Контекст не сохраняет копию памяти.

## Проверки и следующий шаг

Unit-тесты проверяют ротацию, отзыв lease, disabled, fingerprint, лимиты и каталог.
17 wire/CLI-сценариев проверяют настоящие сокеты и CLI, три провайдера в реестре,
worktree, general, переназначение .git, запреты, рестарт и отсутствие owner fallback.
Дополнительно проверяется повреждённая чужая запись: get/history возвращают not_found.

Далее R3 переносит менеджер исполнения и настройки хода. Только после его доверенного
запуска можно автоматически выдавать ключ в окружение провайдера и прикладывать каталог.
Запись через агента, MCP, UI памяти и окончательное удаление остаются отдельными шагами.
Каталог содержит 27 из 98 методов: 15 перенесённых из прежних 86 и 12 новых методов памяти.
