# R2 — подписки на события

Обновлено 11.11.2026. Rust реализует `events.subscribe` и `events.unsubscribe`.
Каталог содержит 7 реализованных методов из 86. Существующий TypeScript-клиент
подписывается на настоящий Rust-сокет тем же протоколом 1.

## Порядок доставки

Номер подписки начинается с 1 отдельно для каждого соединения и повторно не используется.
Ответ `{sub, cursor}` полностью передаётся перед запуском задачи, отправляющей `{sub, event}`.
Курсор ответа относится к общему журналу. История отбирается строго после `since`,
с необязательным фильтром `sessionId` и прежним поведением дробных числовых параметров.

Каждая durable-подписка хранит свой курсор. Уведомление `watch` удерживает только последний
успешно записанный ID. Получатель регистрируется до фиксации границы replay, а писатель
публикует уведомление после подтверждённой записи. Подписка читает недостающее из журнала
порциями до 256 записей и 1 MiB, включая одну большую запись для продвижения курсора.
Новые записи доигрываются тем же путём. Отдельная очередь копий новых событий не растёт.

Задача чтения истории работает отдельно от чтения RPC-запросов. Статус, новые append
и отписка выполняются во время replay. Отписка отменяет задачу, освобождает счётчик и
отключает её ещё не начатые кадры. Кадр, запись которого уже началась, завершается перед
ответом отписки для сохранения NDJSON. Повторная отписка возвращает `removed: false`.

## Общий вывод и пределы

Все RPC-ответы и кадры подписок идут через одного писателя соединения. Бюджет очереди
равен 8 MiB и учитывает байты кадра, который сейчас пишется в сокет. Дополнительный предел
очереди равен 64 кадрам. Разрешены 32 активные подписки на соединение, следующий запрос
получает `invalid_params`. Этот предел также ограничивает задачи и подготовленные порции
вне очереди. Память включает до одной порции и одного кадра каждой задачи, индекс журнала
и крупнейшую запись.

Обычный RPC-кадр имеет предел одной секунды без прогресса записи. Для кадра подписки
предел равен 30 секундам без прогресса. Писатель проверяет отдельные операции `write`,
поэтому постепенно читающий клиент может передавать крупный кадр дольше общего deadline.
Ожидание места в очереди также ограничено. Ошибка писателя уведомляет reader и закрывает
соединение. Задачи, writer и счётчики освобождаются при обрыве и отмене.

При снятии сервером используется `{sub, end}` с `slow_consumer` или `daemon_stopping`.
Кадр завершения доставляется по возможности. Если сокет постоянно не читает, завершение
видно как закрытие соединения после stall deadline. Остановка демона ограничивает ожидание
всех соединений двумя секундами и отменяет оставшиеся задачи.

## Крупные события и UTF-16

Общий журнал сохраняет полную запись. Для подписки событие больше 900 KiB проходит
прежнюю сетку `fitEvent`. Строки внутри `data` обрезаются до 20000, 5000, 1250, 312, 78
и 19 UTF-16 units, с многоточием. Если этого недостаточно, `data` становится `{clipped:true}`.
Ключи и метаданные сохраняются. JSON обрабатывается без преобразования всех строк в Rust
`String`, поэтому сохраняются непарные surrogate и результат обрезания посередине пары.
Сокращённый кадр сравнивается с настоящим Node `fitEvent`.

## Живой канал фаз

`live: true` или `since >= 2**50` выбирает канал `turn.phase`. Его ID назначаются из общей
последовательности выше переданного курсора, включая повторное подключение после рестарта.
Курсор live-канала должен оставаться ниже максимального безопасного целого JavaScript.
Первый кадр содержит `sessionId: "daemon"`, `provider: "pult"` и `data: {reset:true}`.

В Rust пока нет исполняемых сессий, поэтому снимок фаз пуст. После reset подписка остаётся
открытой до отписки или остановки. Этот канал не пишет фазы в durable-журнал и, как нынешний
Node, не применяет фильтр сессии к live-снимку. Передача фактических фаз, объединение
изменений и редакция reasoning подключаются вместе с переносом сессий.

## Проверки

```sh
npm ci && npm run build
node scripts/generate-rpc-catalog.mjs --check
cargo fmt --manifest-path rust/Cargo.toml --check
cargo clippy --manifest-path rust/Cargo.toml --locked --all-targets -- -D warnings
cargo test --manifest-path rust/Cargo.toml --locked
```

Unit-проверки охватывают сохранение UTF-16 при сокращении и предел крупного события.
Интеграции используют нынешний TypeScript-клиент, реальный Unix socket, старый Node-журнал,
параллельные append, большие replay, паузу чтения, отписку, live-reset и остановку демона.
Завершение миграции хранилища, история/снимок окна, сессии и провайдеры идут следующими PR.
