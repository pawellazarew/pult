# M3 — управление памятью владельцем

В настройках появился раздел «Память». Отдельный диалог работает с Rust owner API через обычный
мост Electron. Открытие диалога сохраняет несохранённые настройки. Для доступности требуются все
восемь объявленных методов и рабочее хранилище. Статус `memory.busy` означает временную занятость.
Старый Rust или Node-демон показывает объяснение недоступности.

## Возможности

- Область проекта открытого чата выбирается по умолчанию. Для чата без проекта используется общая область.
- Сохранённые проекты доступны независимо от наличия сессии и исходной папки.
- Список и поиск имеют страницы. Полное содержимое и история загружаются отдельно.
- Создание и правка содержат название, описание, подробности, закрепление и причину изменения.
- Детали показывают автора, версию, время и доступное происхождение session/event/turn.
- Текст памяти выводится как данные. В нём отсутствуют активные инструменты, загрузка изображений и HTML.
- Каждая правка требует `expectedVersion`. Конфликт сохраняет текст редактора и показывает актуальную
  запись. Владелец явно принимает новую базовую версию, затем отдельно сохраняет свою правку.
- При неизвестном результате запроса окно удерживает исходные метод, payload и `commandId`.
  Проверка результата повторяет тот же запрос. Последующий отказ обновления списка не отменяет
  подтверждённую запись.
- Escape, закрытие и переход к другой записи проходят проверку несохранённых изменений. Закрытие
  диалога может сохранить черновик до следующего открытия в том же окне. Фокус и Tab остаются в диалоге.

## Owner API

Окно получает только `memory.projects/list/search/get/history/add/update/forget`. Методы выпуска
credentials и управления scoped контекстом в белый список окна не входят.

`memory.projects({limit?, offset?})` возвращает страницы `projects` с `projectId`, числом живых
записей `count`, временем `updatedAt` и общим `hasMore`. Проекты с одними мягко удалёнными записями
сохраняются в ответе. Точный ID из этого списка можно передать owner CRUD/read API при явном
`scope: "project"` и отсутствии `session`. Проверка существования и операция выполняются под одним
memory lock. Для этого селектора файловая система не читается. Первую запись нового проекта создают
через сессию, как прежде.

`projectId` удаляется из параметров только на owner boundary, затем становится доверенным контекстом.
Allowlist scoped чтения, turn API и MCP сохраняет прежние ограничения. Receipt учитывает выбранный
контекст, поэтому замена селектора с прежним `commandId` возвращает конфликт команды.

## Границы этого шага

`memory.forget` выполняет мягкое удаление. Поиск и новые каталоги исключают запись, история и payload
receipts остаются. Удалённая карточка и её история доступны в текущем окне после удаления. Общего списка
удалённых записей для нового окна пока нет. Physical purge и проверка удаления всех копий остаются
отдельным этапом #106.

Черновик редактора и неизвестный результат удерживаются в памяти текущего окна. Этот шаг не добавляет
дисковый кэш содержимого памяти. Квалификация реальных Claude/Codex/ZCode, native permission chain,
background/warm/questions и рабочее переключение Rust продолжаются отдельно.

## Воспроизводимая проверка

После сборки пакета, оболочки и Rust-демона сквозной прогон запускается командой

```sh
node scripts/memory-window-interop.mjs /absolute/path/to/pultd-rust
```

Он создаёт отдельный `PULT_HOME`, запускает настоящий Rust-демон и подключает окно через обычный
мост. Второй owner-клиент создаёт конфликт версии. Прогон проверяет редактор, закрепление, историю,
поиск, мягкое удаление, сохранение черновика и настроек, а также выбор сохранённого проекта.
Ходы провайдеров не запускаются. Кадры сохраняются в игнорируемом `shell/test-results`.

Дополнительные регрессии находятся в `ui/test/memory.test.ts`, `ui/test/settings.test.ts`,
`shell/test/e2e/memory.test.ts`, mounted `memoryDialog` fixture и Rust memory/scoped interop.
