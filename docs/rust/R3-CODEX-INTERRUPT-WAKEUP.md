# Подтверждение interrupt: terminal flag и уведомления

`cleanup_job` после `turn/interrupt` ждёт подтверждённый `provider_terminal`.
Оба `Notified` регистрируются через pin/enable **до** чтения этого флага.
Иначе router на другом runtime worker может установить флаг и вызвать
`notify_waiters` между проверкой и регистрацией, и cleanup напрасно дождётся
interrupt timeout. Уведомление само по себе не доказывает завершение: после
каждого wake проверяется terminal flag.

Регрессия внедряет изменение флага и единственное уведомление точно между
false-read и ожиданием. Проверены оба источника уведомлений, посторонний wake
и уже завершённый turn. На прежнем порядке первый poll детерминированно остаётся
Pending; на исправленном — Ready, без sleep или увеличения timeout.

Это самостоятельная race многопоточного исполнения. Причина отдельного CI
падения `stale_stop_is_a_noop_for_finished_missing_or_reused_turns` пока не
установлена; test-only диагностика местоположения остаётся нужна. Таймауты,
quarantine и proof очистки процессов этот patch не меняет.
