# R2 — каталог команд и совместимый транспорт

Дата 10.11.2026. Павел выбрал полный перенос Пульта на Rust. Первый шаг R2 связывает
Rust-сервер и нынешний TypeScript-клиент через существующий протокол 1.

## Канонический каталог

`protocol/methods.json` содержит 85 методов нынешнего Node-роутера и расширение
`protocol.catalog`. Состояния Node и Rust записываются отдельно. Значение `unported`
показывает ожидающий переноса метод. Для него оба поля схемы остаются `null`.

В этой поставке Rust реализует `daemon.status`, `daemon.stop` и `protocol.catalog`.
Их схемы входов и ответов входят в каталог. Обязательные поля статуса соответствуют
`DaemonStatus` из `src/core/rpc.ts`. Дополнительные поля статуса разрешены, поэтому
сервер сможет добавлять данные существующих подсистем по мере переноса.

`access` описывает действующие ограничения Node-метода. Ключ вопросов получает
только `perm.request`, ключ runtime получает четыре разрешённых метода своей сессии,
а `runtime.host.*` требует owner-соединения с `client: shell`. Остальные методы
требуют owner. `events.emit` дополнительно отмечен `testOnly`. Реализация сервера
проверяет полномочия при выполнении команды.

`node: reserved` используется для явно отложенных методов из `LATER_METHODS`.
Сейчас этот набор пуст. Расширение `protocol.catalog` получает `node: extension`,
пока Node-роутер не начнёт его обслуживать.

## Генерация и проверка

После `npm ci` выполнить из корня checkout следующие команды.

```sh
node scripts/generate-rpc-catalog.mjs
node scripts/generate-rpc-catalog.mjs --check
npm run build
node --test dist-test/rpc-catalog.test.js
```

Генератор создаёт `src/core/methodCatalog.ts`. Файл экспортирует метаданные,
множество имён методов и типы входов/ответов трёх реализованных Rust-команд.
Изменения выполняются в JSON-каталоге, затем генерируется TypeScript.

Проверка извлекает строковые dotted `case` из AST `src/daemon/server.ts`, читает
буквальный набор `LATER_METHODS` и сверяет `PROTOCOL_VERSION`. Добавление или удаление
метода требует обновления каталога. `--check` также обнаруживает устаревший
сгенерированный TypeScript и завершает работу с кодом 1, сохраняя файл на диске.

Граница инвентаря проходит по этим объявлениям роутера. Условия внутри методов,
привязки scoped-ключей и семантика прав проверяются при ревью реализации и её тестами.
Переход на динамическую регистрацию команд требует изменения извлечения инвентаря.

## Порядок расширения

При переносе следующего метода обновить его `rust`, добавить фактические схемы
входа/ответа и реализовать обработчик. Проверить поведение текущим клиентом через
обычный RPC-вызов, включая ошибочные параметры и ограничения доступа. Затем
перегенерировать каталог и выполнить проверку дрейфа.

Дальнейшие этапы R2 добавят хранение, replay и подписки. Существующие сессии,
адаптеры и правила доступа будут переноситься по условиям приёмки плана
`docs/19-PLAN-rust-migration.md`.
