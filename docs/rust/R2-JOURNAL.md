# R2 — журнал событий и чтение с курсора

Обновлено 11.11.2026. Этот шаг добавляет `events.tail`, тестовый `events.emit`
и журнал в основное Rust-ядро. В каталоге реализованы 5 из 86 методов.
Подписки, снимок, история окна, поиск и сессии ожидают переноса.

## Формат и совместимость

Общий файл `events/journal.jsonl` сохраняет NDJSON-конверт нынешнего `PultEvent`.
ID положительные, строго возрастающие и находятся в диапазоне безопасных целых JavaScript.
Старые пропуски ID допустимы. После повторного открытия следующая запись получает последний
номер плюс один. Файл сканируется построчно, в памяти строится индекс смещений.
Чтение начинается с двоичного поиска курсора и читает подходящие записи по одной.
Память занимает индекс, порция ответа и крупнейшая запись. Ограничение размера файла не вводится.

Старые строки сохраняются как исходный JSON. Неизвестные поля и будущие виды событий
остаются в ответе. Для индекса отдельно декодируются ID и UTF-16 units имени сессии.
Это сохраняет строки Node с непарным surrogate, например результат `"🌊".slice(0, 1)`.
RPC и Rust CLI возвращают такие строки без потери кодовых единиц.

Проверка при открытии принимает нынешний минимальный конверт с ID и строковым `sessionId`.
Новые записи содержат полный набор `id`, `ts`, `sessionId`, `provider`, `kind`, `data`
и необязательный `parentId`. Метки времени новых записей используют UTC с миллисекундами.

## Подтверждение и восстановление

Общий журнал имеет эксклюзивный advisory-lock. Каталоги приватные, файлы проверяются
после открытия с `O_NOFOLLOW` и `O_NONBLOCK`. Symlink, FIFO, hard link и публичные права
отвергаются. Это дополнение к lock владельца демона.

Запись полностью дописывается и проходит `sync_all` до успешного подтверждения.
Номер и индекс обновляются после успешной синхронизации. Ошибка записи или синхронизации
блокирует дальнейшие append в этом экземпляре. После ошибки исход записи неизвестен
до повторного открытия и replay. Пакетный `events.emit` может сохранить часть пакета
до ошибки, поэтому повтор всего пакета требует сверки журнала.

При открытии сначала проверяются все полные строки. Ошибка JSON, повтор ID, нарушение
порядка или недопустимый ID останавливают открытие без изменения байтов файла.
После успешной проверки обрезается только хвост без завершающего `\n`, включая
синтаксически полный JSON без перевода строки. Исправление синхронизируется с диском.

При создании журнала синхронизируются файл и каталог. Создание каталога событий
также синхронизирует его родителя. Проверки подтверждают падение процесса и инъекции
отказов IO. Испытание реального отключения питания и гарантий накопителя остаётся
отдельной приёмкой.

## Срезы сессий

После общей записи обновляется `events/<session>.jsonl` с нынешними правилами имён.
Имя `journal` использует `_journal.jsonl`, недопустимые имена используют `_other.jsonl`.
Срезы читаются настоящим Node-хранилищем.

Ошибка среза сохраняет уже подтверждённую общую запись. Демон отмечает наблюдавшийся
отказ в `daemon.status.journal.projectionDegraded` до конца запуска. Перед следующей
попыткой срез повторно открывается и его оборванный хвост восстанавливается.
Автоматическое восстановление пропущенных записей среза из общего журнала входит
в следующий шаг хранилища. Статус отражает наблюдавшиеся ошибки текущего запуска.
Полная проверка соответствия всех срезов при старте пока впереди.

## RPC и CLI

`events.tail` сохраняет параметры `since`, `sessionId`, `limit` и ответ `{events, cursor}`.
`since` исключается из результата, а `cursor` всегда равен последнему ID общего журнала.
При чтении страниц продолжать нужно с ID последнего возвращённого события.
Дробные и отрицательные числовые параметры проверяются против нынешнего Node-хранилища.

Ответ ограничен размером кадра. Если выбранный результат слишком велик, приходит явная
RPC-ошибка `internal` с описанием frame budget. Клиент может уменьшить `limit` и продолжить
на том же соединении. Один старый event больше размера кадра доступен библиотеке журнала,
его выдача в урезанном виде относится к переносу `events.get` и истории окна.

`events.emit` доступен только при `PULT_TEST=1`. Он использует нынешний словарь видов,
диапазон количества 1–1000 и результат `{ids, lastEventId}`. Вход `data` требует объект
или `null`. Новые данные тестового метода проходят обычный Rust JSON-парсер и требуют
корректных Unicode scalar values. Чтение старых записей сохраняет весь UTF-16 Node.

```sh
./rust/target/debug/pultd-rust --home /absolute/scratch events tail --since 0 --session chat --limit 100
```

Сервер атомарно публикует приватный маркер `.rust-core-scratch` в новом scratch-home.
Он позволяет повторно открыть собственный `events`. Папки с существующим `events`
без маркера, настройки/реестр сессий и production-пути отвергаются.
Переключение рабочей установки проходит отдельную приёмку миграции.

## Проверки

На локальном macOS прошли следующие команды.

```sh
npm ci && npm run build
node scripts/generate-rpc-catalog.mjs --check
node --import ./scripts/test-language.mjs --test dist-test/rpc-catalog.test.js dist-test/core.test.js dist-test/crash-safety.test.js dist-test/history-pages.test.js
cargo fmt --manifest-path rust/Cargo.toml --check
cargo clippy --manifest-path rust/Cargo.toml --locked --all-targets -- -D warnings
cargo test --manifest-path rust/Cargo.toml --locked
```

Node-проверки дали 56 успешных тестов. Rust содержит 12 тестов журнала, один инвариант
каталога и два интеграционных исполнителя. Они запускают 15 прежних сценариев транспорта
и 13 сценариев журнала через настоящий TypeScript-клиент и Node `createStore`.
Проверки включают raw UTF-16 через CLI, 48 записей четырёх конкурентных клиентов,
SIGKILL после ACK, восстановление хвоста, неизменность повреждённого файла,
инъекции ENOSPC/EIO, отказ второго писателя и ограничение ответа без потери соединения.
Живые провайдеры для этого шага не требуются.
