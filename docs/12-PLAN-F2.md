# Ф2 — окно Пульта (решения лида, 28.09.2026)

Цель: владелец работает в Пульте из окна вместо терминала — заводит агентов, пишет им, видит, что они делают,
и отвечает на разрешения в одном месте. Ф2 идёт **раньше Ф1.5** (просьба владельца 28.09: «удобный UI, хочу уже пользоваться»);
адаптер opencode — после.

Основание: страница v0.6 (оболочка Electron тонкая, fuse `runAsNode` выключен, интерфейс грузится из пакета по `app://`,
с демоном говорит main-процесс через unix-сокет), `07-PLAN-F1.md` §3 (протокол v1, клиент `shell` уже есть в рукопожатии).

## 1. Раскладка
```
ui/            исходники интерфейса (React + TypeScript), собираются esbuild в dist/ui/ (статика: index.html, app.js, app.css, fonts/)
shell/         отдельный пакет Electron: main.ts, preload.ts, свой package.json (electron, electron-builder, @electron/fuses — только тут)
```
Пакет `pult` по-прежнему без рантайм-зависимостей: `dist/ui/` — статика, React вшит в бандл. esbuild, react, react-dom, @types/react —
devDependencies корня. Electron и всё его — только в `shell/`.

## 2. Оболочка (`shell/`)
- Находит пакет pult: `PULT_UI_ROOT` (разработка: корень рабочей копии) → иначе `PULT_HOME/current/lib/node_modules/pult`.
- Поднимает демона так же, как CLI (`ensureDaemon` пакета: служба → kickstart, незагруженная — bootstrap; иначе отсоединённый спавн), подключается к сокету клиентом `shell`.
  Токен демона в рендерер **не уходит никогда**.
- Протокол `app://pult/…` отдаёт файлы только из `<пакет>/dist/ui/` (нормализация пути, выход за корень — 404).
- Мост (preload, `contextBridge`) — `window.pult`: `version` (константа версии моста), `call(method, params)`, `subscribe(since, onEvent)` → отписка,
  `pickFolder()`, `revealPath(path)`, `notify(title, body, target)`, `clipboardFilePaths()` (пути файлов, скопированных в Finder: только
  абсолютные, не больше 64; содержимое файлов окно не получает), `pathsForFiles(files)` (пути перетащенных файлов). main пропускает только методы из белого списка: `daemon.status`, `doctor.run`,
  `agent.start|rename|archive|prompt|read|wait|list|stop|rm|tree|import`, `perm.list|resolve`, `events.subscribe|unsubscribe|tail`, `usage.get`, `provider.reset`,
  `providers.check`, `sessions.external.list|read` (06.10: статус провайдеров, чужие чаты только чтение + импорт копией),
  `project.list|add|remove` (07.10: проекты-папки для дерева «проект → сессии») — и ничего больше
  (никаких `perm.request` и `events.emit`; `daemon.stop` — только кнопкой с подтверждением через отдельный метод моста).
- Безопасность окна: `contextIsolation`, `sandbox`, без `nodeIntegration`, `webSecurity`; навигация и `window.open` запрещены; CSP
  `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; worker-src 'self'; connect-src 'self'`. Fuses: `RunAsNode` off,
  `EnableNodeOptionsEnvironmentVariable` off, `EnableNodeCliInspectArguments` off, `EnableEmbeddedAsarIntegrityValidation` on, `OnlyLoadAppFromAsar` on.
- Переподключение: демон ушёл (стоп, обновление, падение) — плашка «демон недоступен», повтор с растущей паузой, после подключения —
  `events.subscribe {since: последний увиденный id}`: окно доигрывает пропущенное, ничего не теряет.
- Уведомления macOS: новый запрос разрешения и конец хода, пока окно не в фокусе; клик открывает окно на нужном агенте или запросе.
- Закрыть окно ≠ остановить агентов: демон живёт отдельно.
- **Строка меню** (07.10, как у нативных Claude Code и Codex): значок-шаблон (три фейдера из иконки, `build/trayTemplate.png` + `@2x`,
  едет внутри `app.asar`) и рядом число запросов, которые ждут человека (разрешения и вопросы Codex из `perm.list`); подсказка —
  «Пульт · 2 ждут тебя · 1 идёт». Меню: строка демона («Демон 0.2.5 · служба» / «Демон недоступен»); «Ждут тебя» — по пункту на запрос
  («сессия — инструмент» или «вопрос»), клик открывает окно на этом запросе; «Сессии» — до 15, в порядке списка окна, «● название · статус»,
  клик открывает окно на сессии; «Открыть Пульт»; «Выйти из Пульта» — выходит только оболочка, сессии работают в демоне. Модель меню —
  чистая функция (`shell/src/tray.ts`), main строит из неё `Menu`. Обновление — по событиям демона (`status.changed`, `permission.*`,
  `session.started|ended`, `daemon.started`) и смене связи, одной пачкой раз в 200 мс: `daemon.status` + `agent.list` + `perm.list`
  через соединение main, без опроса. Демон недоступен — списков нет (устаревшее не выдаётся за живое), «Открыть» работает. Значок
  живёт и без окна: закрыл окно — видишь, кто ждёт.

## 3. Интерфейс (О1 — «уже пользоваться»)
Язык — русский. Тема — системная, светлая и тёмная. Визуальный язык — тот же, что у страницы v0.6: Geologica / Onest / JetBrains Mono
(шрифты лежат локально в `dist/ui/fonts`, OFL), акцент `#2456D6`, провайдеры: Claude — янтарь, Codex — бирюза, opencode — фиолет;
статусы: готово — зелёный, идёт — акцент, ждёт тебя — янтарь, очередь — серый, ошибка — красный. Плотный интерфейс инструмента, не лендинг.
1. **Слева — агенты**: имя, провайдер, статус-чип, папка/ветка worktree, время последней активности; вверху «+ Агент»; ждущие решения — первыми.
2. **Центр — разговор с агентом**: реплики человека и модели (`message.done`, по ходу — `message.delta`), вызовы инструментов свёрнутыми строками
   (`tool.called` → `tool.finished`, раскрываются), субагенты вложенным блоком (`agent.spawned`/`agent.finished`); поле ввода: Enter — отправить,
   Shift+Enter — новая строка; кнопка «Стоп» во время хода; ошибки хода — текстом причины (у `WaitResult.message`).
3. **Inbox** (бейдж со счётчиком в шапке, панель справа): запросы всех агентов — что просит (инструмент, команда или файл, причина, варианты),
   «Разрешить» / «Отказать» (+ причина). Запрос из текущего агента показывается и прямо в ленте разговора.
4. **Шапка**: демон (версия, режим служба/по требованию, аптайм), страж сети (страна выхода, время проверки), лимиты claude и codex
   (окна 5 ч и 7 дн из `usage.get`), кнопка `doctor` (панель с пунктами и командами «почини»).
5. **«+ Агент»**: провайдер, папка (системный диалог), ветка worktree (необязательно), модель и усилие; первая реплика — сразу там же.
6. **Состояния**: демон недоступен (кнопка «запустить»), провайдер остановлен (кнопка «снять остановку» → `provider.reset`), сеть заблокирована
   стражем (страна, что сделать), лимит (когда сброс).
7. **Горячие клавиши**: ⌘N — новый агент, ⌘1…9 — агенты, ⌘I — Inbox, ⌘Enter — разрешить выделенный запрос, Esc — стоп хода (с подтверждением).

Дополнения протокола, которые понадобились окну в О1 (все — добавочные, старый клиент их не замечает):
событие `message.user {text}` (реплика человека в журнале — лента после повторного открытия), `message` в
`status.changed failed` (причина провала текстом), `daemon.status.providers` (остановлен ли провайдер сейчас),
`checkedAt` в пунктах `net.*` доктора (время проверки стража в шапке); метод моста `copyText` (команды doctor).

**Контекстное окно сессии** (07.10.2026, добавочно): событие `context.updated {used, window, model}` — сколько токенов разговор занимает
в окне модели. Claude: подсказка ответа верхнего уровня (`input + cache_creation + cache_read` из `message.usage`, реплики субагентов
не считаются), окно — `modelUsage[модель].contextWindow` из `result`. Codex: `thread/tokenUsage/updated` своего треда,
`last.totalTokens − last.reasoningOutputTokens` (как `tokens_in_context_window()` в Codex CLI), окно — `modelContextWindow`.
Неизвестное окно менеджер подставляет из прошлого значения той же модели; последнее значение уходит в `agent.list` (поле `context`) и
в реестр — попутно со сменой статуса, без отдельной записи. В окне: в шапке разговора «контекст 48k / 200k · 24%» с тонкой полоской
(до 70% — зелёный, 70–90% — янтарь, дальше — красный), точные числа и модель — в подсказке; в строке дерева `ctx 75%` — только от
половины окна; в подсказке вкладки — всегда. CLI: `pult agent list` пишет `ctx 24%`, `--json` несёт объект целиком.

## 5. Проверки
- Юнит: чистые функции интерфейса (свёртка событий в ленту разговора, статусы, сортировка агентов, формат лимитов) — node:test без DOM.
- e2e: Playwright `_electron` на фальшивых CLI (`PULT_TEST=1`, временный `PULT_HOME`): завести агента, реплика, ответ в ленте, разрешение из Inbox,
  «Стоп», рестарт демона — окно переподключается и доигрывает события с курсора; закрыть окно посреди хода — ход дошёл, после открытия история на месте.
  Скриншоты каждого экрана в светлой и тёмной теме сохраняются артефактами прогона — по ним судит визуал отдельный судья.
- CI: сборка `dist/ui`, типы `shell/`, юнит-тесты интерфейса — всегда; e2e Electron — на macOS-раннере при изменениях `ui/`, `shell/`, `src/`.
- Приёмка О1: лид работает в окне с настоящими агентами (haiku) — заводит, пишет, отвечает на разрешения, переживает рестарт демона.
  Приёмка Ф2 целиком — неделя владельца в окне вместо терминала.

## 6. Статус О1 (28.09.2026, ветка `feat/f2-m1-window`)
**Сделано — код и проверки; приёмка лида с настоящими агентами — впереди.**
- `ui/` → `dist/ui` (React 19 вшит в `app.js` ~228 КБ, шрифты OFL копируются из `@fontsource-variable/*` при сборке);
  модель окна — чистые функции (свёртка событий, агенты, Inbox, лимиты, doctor, горячие клавиши, markdown, diff).
- `shell/`: main + preload одним CJS (esbuild), `app://pult`, белый список методов, переподключение с курсором,
  уведомления, `copyText`. Код протокола main грузит из найденного пакета (`import()`), копии в оболочке нет.
- О3, что из кода: глагол `pult ui` (Pult.app → рабочая копия → подсказка, код 1); `npm run dist:mac` —
  Pult.app arm64 с fuses из §2 и ad-hoc подписью, иконка `shell/build/icon.svg` → `icon.icns`;
  `scripts/check-app.mjs [--launch]`. Установка владельцу (`/Applications`, служба, `~/.local/bin/pult`) — руками лида.

Проверки: пакет `npm test` (юнит окна — node:test без DOM), shell unit, e2e Playwright `_electron` на фальшивых CLI
(связь, безопасность, сценарии, 10 экранов в светлой и тёмной теме), `check-app.mjs --launch` на собранном Pult.app.

Отступления (с замером):
- **node для демона.** `process.execPath` оболочки — бинарь Electron, а `RunAsNode` выключен: `ensureDaemon` получил
  `nodePath`; порядок поиска `PULT_NODE` → `PULT_HOME/node-path` → PATH → Homebrew. Нет node — «запустить» отвечает
  `no_node`, на Electron не откатывается.
- **Протокол, добавочно:** `message.user`, `message` в `status.changed failed`, `daemon.status.providers`, `checkedAt`
  у `net.*` (§3). Без `message.user` реплики человека не было в журнале — лента после повторного открытия была пустой.
- **`agent.start` без события** — окно дополнительно опрашивает `agent.list` раз в 4 с (без этого агент, заведённый
  из CLI, не появлялся — пойманный флейк e2e).
- **`doctor.run {net:true}` под тестом** ходил настоящим curl через системный прокси (виден на снимке) — теперь та же
  подмена стража, что у ходов.
- **Мост шире списка §2:** `onConnection`, `startDaemon`, `stopDaemon` (подтверждение системным диалогом в main),
  `onNavigate`, `copyText`, `testMode`. `events.subscribe` через `call` отказывает `use_subscribe`.
- **Проверка fuses делом.** Playwright `_electron` управляет приложением через `--inspect`, который fuse выключает,
  поэтому живой прогон Pult.app идёт через `--remote-debugging-port` (ключ Chromium, не node) и CDP.
  Замер: `ELECTRON_RUN_AS_NODE=1 … -e` не печатает, `NODE_OPTIONS=--require` не исполняется, `--inspect` отладчик не
  открывает, app.asar с правкой заголовка падает на старте (SIGTRAP, integrity).
- **Сборка без скачивания:** `electronDist` = `node_modules/electron/dist` — в Pult.app тот же Electron 44.4.5,
  что в e2e.

Известные пределы О1: окно доигрывает весь журнал при открытии (журнал за недели — секунды до первого показа);
клик по системному уведомлению e2e не покрыт (в тесте уведомления пишутся в main); плашки «провайдер остановлен»,
«сеть заблокирована» и лимит закрыты юнитами модели, на снимках их нет; markdown упрощён; Pult.app только arm64,
подпись ad-hoc (Gatekeeper на другой машине не пустит без `xattr -d com.apple.quarantine`); Linux-путь CI
(PULT_E2E=0) проверяется только на раннере.

Поправка 30.09.2026 (замер на настоящем launchd, `docs/08-PLAN-F1-M4.md` §10): окно зовёт `doctor.run {net: true}` при открытии, а
доктор шёл через `spawnSync` на событийном цикле демона — под службой с `ProcessType Background` демон не отвечал на `hello`
44–94 с. Исправлено в 0.2.2: запуски доктора асинхронные, служба — `Standard`. Медленный первый ход под службой (тот же фоновый
приоритет наследовал и `claude`) после `pult daemon install` должен уйти — настоящим ходом это ещё не перемерено.
