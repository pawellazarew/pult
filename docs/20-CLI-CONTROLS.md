# Управление Пультом и CLI из окна

В нижней панели навигации кнопка `CLI` открывает управление демоном,
диагностикой и установленными Claude Code / Codex. Тот же экран доступен в меню помощи.

Демон можно запустить, остановить и перезапустить. Остановка и перезапуск требуют
системного подтверждения и прерывают активные ходы. При перезапуске окно ждёт закрытия
старого соединения, запускает новый процесс и восстанавливает подписки. После
намеренной остановки автоматического запуска нет.

Диагностика работает и без демона. В этом случае оболочка вызывает установленный
`pult doctor --json --no-net` в отдельном ограниченном по времени процессе. Проверка
сети доступна после запуска демона. Время отчёта видно на экране. Его можно скопировать,
открыть подробности, папку данных или журналы.

## Claude Code и Codex

Панель показывает выбранный Пультом путь, раскрытый путь, версию и источник установки.
Состояние входа берётся из диагностики. Сбой запуска или неразобранный ответ сообщает
о неудавшейся проверке и сам по себе не считается доказательством выхода из аккаунта.

Установка, обновление и вход открываются в отдельном видимом окне macOS Terminal.
Перед запуском системный диалог показывает фиксированную команду. Окно передаёт только
имя провайдера и действие, произвольные команды рендерер не передаёт. OAuth выполняется
самим CLI и браузером провайдера. Пульт не получает токены, одноразовые коды или вывод входа.

- Установка использует официальный нативный установщик выбранного провайдера.
- Обновление Homebrew сохраняет prefix и тип пакета выбранного бинаря.
- Обновление npm сохраняет prefix найденного пакета.
- Нативный launcher обновляется через собственную команду. Для старого Codex без
  self-update используется официальный установщик только при выбранном стандартном
  `~/.local/bin/codex`. Нестандартная установка требует явного ручного обновления.
- CLI внутри `.app` открывает приложение-владелец для его обновления. Пульт отмечает
  передачу управления и предлагает перепроверить версию после обновления приложения.

Перед установкой, обновлением и входом проверяется настроенный профиль сети и страж
страны выхода. После системного подтверждения маршрут проверяется повторно.
Разрешённый proxy передаётся ребёнку через приватный временный env-файл,
который удаляется сразу после загрузки. Его значения не входят в показанную команду.
OAuth-страница использует сеть браузера. Обновление приложения-владельца CLI использует
сетевые настройки самого приложения.

Терминальный процесс получает тот же HOME и базовое окружение по белому списку,
что дети Пульта. `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, API-ключи и переменные чужих сессий
из окружения Terminal не наследуются. Для каждого действия создаётся приватный
скрипт в `PULT_HOME/run/maintenance`. Пульт читает только небольшой файл кода выхода.
При незавершённом действии результат остаётся неизвестным, позднее завершение
можно увидеть при повторном открытии панели. Для повторного запуска после неизвестного
исхода системный диалог напоминает проверить прежнее окно Terminal.

Панель показывает активное действие или последнее завершившееся. Это состояние хранится
до завершения main-процесса окна. После полного выхода из приложения готовность CLI
проверяется заново, история отдельных операций не восстанавливается.

## Проверка

Юнит-тесты `shell/test/unit/maintenance.test.ts` выполняют только fake CLI и fake curl.
Они проверяют выбор установки, quoting, изоляцию профиля, ошибку скачивания,
конкурентный запуск, поздний результат и безопасное чтение файлов состояния.

`shell/test/e2e/maintenance.test.ts` проходит обычные кнопки окна и IPC в отдельном home.
Terminal, установщики и OAuth заменены швом `PULT_TEST=1`. Настоящие провайдеры,
учётные записи и установленный демон пользователя в этом прогоне не меняются.
