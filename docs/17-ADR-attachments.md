# ADR-17: вложения в поле ввода

**Статус:** принято для 0.3.15 / окна 0.1.21. **Дата:** 28.10.2026.

## Контекст

Поле ввода раньше вставляло только путь файла. У скриншота из памяти пути нет, а временный файл мог исчезнуть
до чтения агентом. Пользователь не видел, какие файлы прикреплены, и не мог убрать один из них отдельно от текста.
Демон принимает текстовые реплики; Claude и Codex уже умеют читать файлы по путям. Изменять протокол провайдеров
для этого не требуется.

## Решение

Сохраняем снимок обычного файла при добавлении, показываем его карточкой отдельно от текста, при отправке
добавляем блок путей в существующий prompt. Файл без пути передаётся ограниченным массивом байтов.
Папка — ссылка с явной подписью, без рекурсивного копирования. Отправка ждёт окончания сохранения и проверяет
наличие файлов. При отказе карточки и текст возвращаются; новые вложения не затираются.

- Оболочка получает `File` через `attachments.files()`: preload сам извлекает native path или читает bytes.
  `attachments.clipboard()` читает пути Finder в main; renderer не выбирает произвольный исходный путь.
- `attachments.import()` разрешает bytes либо уже сохранённый файл внутри `attachments` — для переноса
  из черновой папки в папку итоговой сессии. Папку назначения определяет main.
- Файлы: `PULT_HOME/attachments/<сессия>/<дата>/…`, права 0600/0700, уникальные имена без перезаписи.
  25 МБ/файл, 1 ГБ/день. Native input обязан быть regular file; ссылки и специальные файлы не копируются.
- Новый диалог использует случайное валидное имя `draft-…`, независимое от редактируемого имени формы.
  Перед созданием файлы копируются в папку итоговой сессии; только итоговые пути идут в prompt. Ошибка копирования
  оставляет форму открытой. Сложная транзакция регистрации/rename/отката не нужна: черновик остаётся для повтора.
- В localStorage — только метаданные до 20 вложений, без bytes/base64. PNG/JPEG-превью читается через отдельный
  метод только из папки своей сессии; SVG и HTML не исполняются. После удаления оригинала сохранённая копия доступна.
- Очистка использует существующие 30 дней по mtime. Срок указан возле карточек; удаление карточки не удаляет файл,
  который мог попасть в историю или очередь. Для долгоживущей беседы старое вложение может потребовать повторного
  добавления. Отдельную модель постоянных файлов этот шаг не вводит.

## Рассмотренные варианты

| Вариант | Результат |
| --- | --- |
| Только путь исходника | Просто, но временный файл исчезает и не существует для картинки из памяти |
| Base64 в prompt и localStorage | Раздувает историю, упирается в квоту браузера, требует изменений провайдеров |
| Копии + карточки + пути при отправке | Выбран: совместим с демоном и существующим доступом к папке вложений |
| Реестр opaque IDs и транзакционный перенос | Полезен для постоянных вложений, но требует нового daemon API без нужды для этого шага |

## Независимая проверка и источники

Решение обсуждено с Claude Code через отдельный read-only вызов 28.10.2026 до завершения реализации.
По ревью сужены входы bridge до реальных `File` и системного буфера; сохранены проверки до отправки,
metadata-only drafts, раздельные копии сессий и явный срок хранения. Предложение постоянного реестра IDs
оставлено за рамками, поскольку протокол реплик остаётся текстовым.

Паттерны изучены по официальным источникам:

- [VS Code: Add context to chat](https://code.visualstudio.com/docs/chat/copilot-chat-context): файлы/изображения как контекст,
  перетаскивание и снимок браузера.
- [Cursor: image input](https://prod.cursor.com/docs/agent/prompting): drop и paste изображений в поле запроса.
- [Claude: upload files](https://support.claude.com/en/articles/8241126-upload-files-to-claude): добавление через «+», drop и paste.
- [Electron: webUtils](https://www.electronjs.org/docs/latest/api/web-utils): у созданного в JS `File` может не быть дискового пути.

## Приёмка

Backend unit и настоящий Electron проверяют File без пути, снимок после удаления исходника, Finder clipboard,
отказ произвольному source path страницы, лимиты, симлинки, черновую/итоговую сессию, thumbnails и reload.
UI отдельно проверяет передачу только сохранённых путей, удаление карточки и отсутствие base64 в localStorage.
