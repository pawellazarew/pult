# Проверка Пульта

Работай из корня отдельного checkout Пульта. Для выбора проверок прочитай
`docs/rust/R0.md`; после изменений Preview/мобильных драйверов дополнительно
`docs/18-RUNTIME-VERIFICATION.md`. Полный Rust-план — `docs/19-PLAN-rust-migration.md`.

1. Зафиксируй commit, изменения дерева и выбранные риски. Выбери строки карты R0,
   затронутые изменением. Проверь существование перечисленных тестов: при переименовании
   поправь карту, не пропускай проверку молча.
2. Выполни `npm ci && npm run build`. Для целевых тестов используй
   `node --import ./scripts/test-language.mjs --test dist-test/<name>.test.js`;
   UI unit лежат в `dist-ui-test`. Не подменяй реальные границы тестовыми getter/assertions.
3. Для полной проверки используй `./scripts/ci-check.sh`. Для Electron сначала прочитай
   `shell/test/e2e/harness.ts` и `shell/package.json`: изолированный harness сам создаёт данные.
   Не запускай реальный установленный Пульт и не переключай его backend ради теста.
4. Для замеров выполни команды из R0. Fixture baseline не требует CLI-подписок.
   Реальный модельный smoke выполняй только в авторизованном объёме задачи, в scratch-проекте;
   записывай версию CLI и конкретный факт ошибки доступа, не делай вывод о разлогине по одному отказу.
5. Запиши для каждого выбранного сценария `passed`, `failed`, `not run` или `blocked`,
   команду, commit, код завершения и путь к логу/снимку. Логи сохраняй вне checkout или в
   игнорируемых test-results. Не публикуй токены, реальные разговоры и конфигурацию аккаунтов.

Готово, когда каждая выбранная строка имеет фактический результат, новые отказы объяснены,
а изменения дерева после проверки совпадают с ожидаемыми. Успешные unit не подтверждают
живые устройства, микрофон, производительность UI или работу реальной модели.
