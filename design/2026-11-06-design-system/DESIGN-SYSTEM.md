# Дизайн-система Пульта — черновик v0.2, 06.11.2026

Статус: **черновик**, код приложения не менялся. `tokens.css` лежит рядом и не подключён.
Основа — `AUDIT.md`. v0.2 — после критики Codex. Что принято и что отклонено, записано в `CODEX-CRITIQUE.md`.

## 0. Зачем и пять правил

Повод — три ошибки в колонке ввода: кнопки очереди вылезают за рамку, строка очереди шире поля, пилюля субагентов
стоит не по краю поля. Все три относятся к одному классу: у интерфейса нет общих правил размеров, краёв и переполнения.
Система закрывает именно этот класс. Новая палитра и новый стиль в её задачу не входят: цвета и шрифты остаются
утверждёнными 05.11.

1. **Одна колонка.** Лента, всё, что над полем ввода, и само поле стоят в одной колонке с общими внешними краями.
2. **Три высоты контролов.** `sm / md / lg` = 24 / 28 / 32 при шрифте 14; в одном ряду у контролов одна высота.
3. **Текст сдаётся первым.** При нехватке места сначала обрезается текст, затем подписи превращаются в иконки.
   Действия не выходят за рамку и не переносятся по одному.
4. **Размер задаётся контейнером, а не окном.** Компоненты сворачиваются по контейнерным запросам к своей колонке.
   Viewport-брейкпоинты остаются только каркасу окна.
5. **Только токены.** Цвет, кегль, радиус, отступ, высота и слой берутся из `tokens.css`. Литерал допустим только
   для геометрии: рамка 1px, смещение иконки. Исключение — в файле компонента с комментарием.

## 1. Слои токенов

| Слой | Пример | Кто пишет | Кто читает |
|---|---|---|---|
| Примитивы | `--l-gray-600`, `--d-blue-300` | только `tokens.css` | только семантика |
| Семантика | `--ink`, `--panel`, `--fail-soft`, `--control-md`, `--radius-lg`, `--text-sm` | `tokens.css` | весь CSS |
| Компонентные | `--chip-h`, `--queue-item-pad` | CSS компонента | только этот компонент |

**Семантические имена цветов не меняются** (`--ink`, `--mut`, `--hair`, `--line`, `--panel`, `--sunk`…).
У них около тысячи использований, они короткие и уже семантичны. Переименование в `--color-text-primary` дало бы дифф
на тысячу строк без пользы для пользователя. Новые токены названы в том же стиле.

**Одна строка на цвет через `light-dark()`.** Сегодня каждый цвет записан четыре раза:
системная светлая и тёмная тема, явная светлая и тёмная. `light-dark(светлый, тёмный)` выбирает значение
по `color-scheme`, а её уже выставляет `useAppearance.ts` через `data-theme`. Нужен Chromium 123+,
в Electron 45 он заметно новее. `light-dark()` принимает только цвета. Поэтому геометрия большой тени,
которая в тёмной теме другая, задана отдельным блоком — это единственное исключение.

**Каскад.** `tokens.css` лежит в `@layer tokens`. Любое объявление вне слоя сильнее слоя. Поэтому в PR, где
файл подключается, старые определения в `styles.css` и `appearance.css` удаляются **в том же коммите**.
Владелец каждого объявления — один файл (§13).

**Паритет раньше улучшений.** Перенос токенов (PR 3) повторяет текущие значения один в один. Слияние почти
одинаковых цветов (`--faint`/`--mut`, `--user-surface`/`--sunk`, `--amber`/`--wait`) помечено в `tokens.css` как
CANDIDATE и решается отдельным PR по снимкам.

### Акцент, «на заливке», фокус

`--accent`, `--accent-soft`, `--accent-edge` не меняются. Новые токены `--on-accent`, `--on-ok`, `--on-wait`, `--on-fail`
задают цвет текста и иконки на сплошной заливке. Они заменяют литералы `#fff / #0B1220 / #07140C / #1B1206` в шести
правилах. `--focus-color` — сплошной `--accent` (§9).

### Состояния и провайдеры

Состояние (`ok / run / wait / queued / fail`) и провайдер — разные оси, смешивать их нельзя.
У каждого цвета тройка: `base` для текста и иконки, `-soft` для заливки (8–11 %), `-edge` для рамки (32–36 %).
Недостающие `--ok-edge` и `--wait-edge` добавлены. У diff своя заливка (`--add-soft`, `--del-soft`): альфа отличается
от `--ok-soft`/`--fail-soft`, и паритет здесь важнее симметрии.

Провайдеры называются по имени провайдера: `--prov-claude`, `--prov-codex`, `--prov-zcode`, `--prov-opencode`,
у каждого есть `-soft`. Старые `--claude / --teal / --glm / --oc` остаются псевдонимами до конца миграции.

Цвет не может быть единственным носителем смысла. У состояния всегда есть подпись («Ждёт ответа», «full») или иконка —
этого требует REVIEW от 27.10.

## 3. Типографика

Ступени вычисляются от настройки «Размер шрифта» (`--ui-font-size`: 12, 13, 14, 15, 16, 18, 20; по умолчанию 14).
Смещение задано в пикселях, а не множителем, чтобы иерархия не менялась при любом базовом кегле. Нижняя граница —
10 px. При базе 12 ступени `2xs`, `xs` и `sm` совпадают (10 px): это осознанное решение, мельче 10 текст не читается.

| Токен | При 14 | При 20 | Где |
|---|---|---|---|
| `--text-2xs` | 10 | 16 | бейджи, счётчики, капс-метки (`.lbl`, `.tag`) |
| `--text-xs` | 11 | 17 | время, метаданные, подписи под полем |
| `--text-sm` | 12 | 18 | контролы, чипы, строки очереди, меню |
| `--text-md` | 13 | 19 | строки сайдбара, инструменты, карточки Inbox |
| `--text-base` | 14 | 20 | интерфейс по умолчанию |
| `--text-lg` | 15 | 21 | текст реплик, заголовок беседы |
| `--text-xl` | 17 | 23 | h2/h3 в Markdown, заголовок диалога |
| `--text-2xl` | 20 | 26 | h1 в Markdown, пустые экраны |
| `--text-code` | 12.5 | 18.5 | моноширинный текст в ленте |

Восемь ступеней и код вместо 25 значений. Полупиксель остаётся только у `--text-code`. Межстрочные интервалы:
`--leading-none 1` для контролов фиксированной высоты, `-tight 1.3`, `-ui 1.45`, `-body 1.6`. Веса: 400 / 500 / 600.
Проверка — все три шрифта интерфейса (Onest, Geologica, системный) при 12, 14 и 20.

## 4. Отступы

Шаг 4 px: `--space-4, -8, -12, -16, -20, -24, -32, -40`. Полушаги `--space-2, -6, -10` разрешены только
**внутри** контролов — для паддингов чипа и кнопки — и не используются между блоками. Вместо 33 разных паддингов
и 18 разных gap остаётся 11 значений.

Плотность «компактно» (`--density-space: .8`) умножает только промежутки раскладки (`--gap-stack`, `--gap-section`).
На контролы она не действует, иначе нарушится правило трёх высот.

## 5. Радиусы

| Токен | px | Где |
|---|---|---|
| `--radius-xs` | 4 | kbd, inline-код, тег |
| `--radius-sm` | 6 | чип, кнопка sm, пункт меню, контрол внутри поля ввода |
| `--radius-md` | 8 | кнопка md/lg, строка списка, строка очереди, поле формы |
| `--radius-lg` | 12 | карточка, поповер, меню, диалог |
| `--radius-xl` | 16 | поле ввода (все три: беседа, черновик, временный чат), реплика человека |
| `--radius-full` | 999 | пилюля, точка, круглая кнопка отправки |

Ориентир для вложенных элементов: внутренний радиус ≈ радиус родителя − его паддинг, округлённый до ближайшей
ступени и не меньше `--radius-xs`. Это ориентир, а не формула. У контролов в поле ввода по формуле выходит 4,
но выбран `--radius-sm` (6), потому что так эти контролы совпадают с чипами в остальных местах.

## 6. Контролы

| Размер | Высота при 14 / 20 | Паддинг | Иконка | Кегль | Где |
|---|---|---|---|---|---|
| `sm` | 24 / 30 | 6 | 14 | `--text-sm` | плотные строки: очередь, инструмент, вкладка субагента, копирование |
| `md` | 28 / 34 | 10 | 14 | `--text-sm` | по умолчанию: шапки, панели, футеры диалогов, Inbox |
| `lg` | 32 / 38 | 10 | 16 (18 у отправки) | `--text-sm` | панель поля ввода целиком |

- **Высота следует за кеглем:** `--control-md = max(28px, --text-sm + 16px)`. При 14 получается ровно 24 / 28 / 32,
  при 20 — 30 / 34 / 38. С фиксированной высотой крупный шрифт упирался бы в потолок.
- **Одна высота на ряд.** Ряд — это flex-контейнер с контролами: панель поля ввода, строка очереди, футер диалога,
  шапка беседы. Исключения для «главной» кнопки и микрофона нет. Многострочные контролы (textarea, строка очереди
  в правке) получают высоту по содержимому — это не ряд.
- **Минимальная цель — 24 × 24** (`--hit-min`, WCAG 2.5.8). Узкий сегмент split-кнопки (шеврон диктовки) — 24, а не 20.
- Высоту задаёт `height`, а не `min-height + padding`: тогда чипы с иконкой 16 и без неё получаются одинаковыми.
- Внутри контрола `line-height: 1`, вертикальное выравнивание — `align-items: center`.
- Размеры для касания (будущий PWA) — отдельная политика плотности с тестами, не в этом черновике.

## 7. Раскладка: колонка беседы

```
.conv  (container: conv / inline-size)
│ gutter │ ←────────── --column-max (764) ──────────→ │ gutter │
│        │ Ответ модели: левый край текста                  │        │  .feed > .feed-inner
│        │ (◉ 3 субагента)                                  │        │  .subagent-track
│        │ ┌ ≡ 1 Проверь ещё раз, что миг… ✎ ➤ × ┐          │        │  .queue  > .queue-item
│        │ ┌──────────────────────────────────────┐          │        │  .composer > .box
│        │ │ Реплика…                             │          │        │
│        │ │ [◯ opus ⌄][◔⌄][доступ ⌄] ◔   🎙⌄ + ■ ➤ │        │        │
│        │ └──────────────────────────────────────┘          │        │
│        │ ⏲ Доступ сменится после хода                     │        │  .access-strip
```

**Три направляющие.** *Внешний край* — рамка блока. *Край содержимого* — рамка плюс паддинг. *Край текста* —
там, где начинается первая буква. Обязателен только внешний край: его проверяет тест. Два других — ориентиры
внутри компонента, и общие правила колонки их не обнуляют.

1. **Ширина задаётся одной формулой** — классом `.column-block`:
   `width: min(100% - 2 * var(--column-gutter), var(--column-max)); margin-inline: auto`.
   Своего `max-width` и горизонтального паддинга у такого блока нет. Сегодня есть пять разных определений.
2. **Где применяется.** Класс получает любой блок, у которого родитель шириной с `.conv`: `.feed-inner`,
   `.subagent-track`, `.queue`, `.composer`, а также `.parent-callout` внутри `.subagent-view` (это не прямой ребёнок
   `.conv`, но той же ширины). Черновик и временный чат — такие же блоки. Класс всегда получает **обёртку**
   (`.composer`, обёртку `.draft-box`, обёртку `.temporary-box`), а не саму рамку: паддинг рамки — это край
   содержимого компонента, и правило колонки его не обнуляет.
3. **Внешний край каждого блока совпадает с внешним краем поля.** Пилюля, строка очереди, плашки и `access-strip`
   начинаются ровно там же, где `.composer .box`. Левый край текста ленты — тоже.
4. **Полоса прокрутки ленты.** Классическая полоса (подключена мышь) отнимает ширину только у ленты. `.feed` получает
   `scrollbar-gutter: stable both-edges`: место резервируется симметрично, и центр колонки не сдвигается. На узкой
   колонке допуск — ширина полосы, тест это учитывает.
5. **Гаттер.** 24 px при ширине колонки от 600 px, 12 px на более узкой. Переключает `@container conv`, а не `@media`.
6. **Вертикальный ритм.** Между блоками колонки — `--space-8`, внутри очереди между строками — `--space-4`.
7. **Каркас окна** (сайдбар, Inbox, файлы, режимы «Расширенный» и «Фокус» с рейкой 64 px) задают
   `WorkspaceLayout.tsx` и `model/panelSizes.ts` inline-колонками сетки и собственными порогами 950 / 1050 / 1200.
   Сокращение viewport-брейкпоинтов — отдельный PR вместе с этой моделью, а не только правка CSS. Колонку беседы
   оно не затрагивает: она живёт по своему контейнеру.

## 8. Переполнение и обрезка

1. **Строка состоит из трёх зон.** `[ведущие: flex none] [содержимое: flex 1 1 0; min-width 0] [действия: flex none]`.
   `min-width: 0` нужен **прямому** flex-ребёнку с текстом — на внуке он не помогает. Именно так и возник баг очереди.
   Зона содержимого — это и тело правки: у `.queue-edit-body` то же правило.
2. **Ellipsis работает только на блочном элементе.** Утилита `.truncate`: `display: block; min-width: 0; overflow: hidden;
   text-overflow: ellipsis; white-space: nowrap`. На inline-`span` правило не срабатывает.
3. **`nowrap` без обрезки запрещён** в зоне содержимого. Допустим в зоне действий и у чисел.
4. **Порядок сдачи места:** (а) обрезается текст содержимого → (б) у вторичных действий скрываются подписи, остаются
   иконки (`aria-label` и `title` обязательны с первого дня) → (в) вторичные действия уходят в меню «⋯» → (г) только
   после этого ряд переносится, причём **группой целиком**: настройки отдельно, действия отдельно.
   Главное действие (отправить, стоп) не прячется никогда.
5. **Не обрезается то, по чему принимают решение:** счётчики, номер в очереди, состояние «Ждёт ответа».
   Режим доступа сохраняет **текст** в любой ширине: подпись обрезается не короче 12ch, а `full` дополнительно
   выделен цветом и иконкой. Одной иконки щита недостаточно.
6. **Полный текст должен быть доступен.** У обрезанного — `title` или тултип, у реплики в очереди — ещё и правка.
7. **Многострочные превью** обрезаются через `line-clamp: N` (`-webkit-line-clamp`), а не через `max-height`.
8. **Длинные слова без пробелов** (пути, хэши, URL): в прозе — `overflow-wrap: anywhere`; пути в контролах
   сокращаются посередине (`shortPath`), потому что конец пути важнее.
9. **У каждого чипа свой потолок:** модель — 180 px (150 в узком поле), остальные — по содержимому.
   Иконка и шеврон `flex: none`, сжимается только подпись.
10. **Смешанное содержимое** (иконка + точка состояния + текст, как во вкладке субагента) оборачивает текст в
    отдельный `.truncate`. Ellipsis на самой кнопке с текстовыми узлами вперемешку не работает.

## 9. Фокус

- Базовое правило: `:focus-visible { outline: var(--focus-width) solid var(--focus-color); outline-offset: var(--focus-offset) }`.
  Это повторяет действующее правило из блока «редизайн A» (`styles.css`, сплошной акцент 5.81 : 1, offset 2).
  Раннее правило с `--accent-edge` перекрыто им и удаляется. Контраст по WCAG 1.4.11; обзор фокуса по 2.4.11 —
  отдельно: фокус не должен прятаться под липкими блоками и поповерами.
- **Внешнее кольцо по умолчанию.** На залитых контролах (отправка, primary) оно всегда внешнее: между заливкой
  и кольцом остаётся зазор цвета фона, поэтому акцент на акценте виден.
- **Внутреннее кольцо** (`outline-offset: calc(-1 * var(--focus-width))`) — только у незалитых элементов внутри
  контейнера с `overflow: hidden`: строки сайдбара и очереди, вкладки. На залитых — никогда.
- **Поле ввода.** У textarea `outline: none` — санкционированное исключение: роль кольца выполняет `.box:focus-within`
  (рамка сплошным `--accent`, 5.81 : 1, и мягкая тень `0 0 0 2px var(--accent-soft)`). Сейчас рамка `--accent-edge`
  даёт 1.89 : 1; это исправляет PR 4. То же у черновика и временного чата.
- **Опасный контекст** (`full`): подсветка поля и кольца — `--focus-color-danger`.
- `outline: none` разрешён только с заменой, которая видна с контрастом ≥ 3 : 1. Каждое такое место — в списке
  исключений храповика (§12).

| `--z-toast` | 200 | уведомления |

Затемнение всегда ниже своей поверхности. Меню и поповер, которые должны выходить из ящика или диалога, рисуются
порталом в `body`; сейчас так делает только просмотр картинок. Локальные `z-index` (−1, 1, 2) живут внутри
компонента с `isolation: isolate` и в глобальную шкалу не входят. Порядок работ: сначала порталы и контексты
наложения, потом перенумерация.

Тени: `--shadow-sm` — поле ввода, `--shadow-md` — плавающая кнопка, `--shadow-lg` — меню, поповер, диалог.
Движение: `--dur-fast 120`, `--dur-base 180`, `--dur-slow 260`, `--ease-out`. При `prefers-reduced-motion`
длительности обнуляются в самих токенах.

## 11. Компоненты

Формат: анатомия → размеры → состояния → переполнение. Имена классов целевые; существующие классы сохраняются.

### 11.1 IconButton — `.icon-btn`

- **Анатомия:** квадрат с одной иконкой по центру; `aria-label` и `title` обязательны.
- **Размеры:** `sm / md / lg`, иконка 14 / 14 / 16. Вариант `round` (`--radius-full`) — только у главного действия
  поля ввода (отправить, стоп).
- **Тона:** `ghost` по умолчанию (прозрачный, `--mut`), `solid` (`--accent` + `--on-accent`), `danger`
  (`--fail` на прозрачном, hover `--fail-soft`).
- **Состояния:** rest · hover (`--sunk`, текст `--ink`) · active (`--selected`) · `aria-pressed="true"`
  (`--selected` + `--ink`) · focus-visible (кольцо по §9) · disabled (opacity .5, без hover) ·
  busy (`aria-busy`, вместо иконки спиннер того же размера, ширина не меняется).
- **Переполнение:** не сжимается (`flex: none`), подписи нет.
- Заменяет: `.footer-icon`, `.chrome-icon`, `.msg-copy`, `.help-btn`, `.subagent-tab-close`, `.attach-picker`,
  `.dictation-mic`, удаление в очереди, круглые отправку и стоп.

### 11.2 Button — `.btn`

- **Анатомия:** `[иконка?] подпись [kbd?]`, gap `--space-6`.
- **Размеры:** `.btn-sm / .btn / .btn-lg`; паддинг 6 / 10 / 10; радиус `--radius-sm` у sm, `--radius-md` у md и lg.
- **Тона:** `default` (`--panel` + рамка `--line`, hover — рамка `--line-strong`), `primary`, `ok`, `danger`, `ghost`.
- **Состояния:** как у IconButton; при `busy` подпись остаётся, спиннер заменяет иконку, ширина та же.
- **Переполнение:** подпись не переносится. В зоне действий кнопка **схлопывается в IconButton** по контейнерному
  запросу родителя: подпись лежит в `.label` и прячется как `sr-only`. Поэтому у любой кнопки, которая может
  схлопнуться, иконка обязательна.

### 11.3 SelectChip — `.chip-select` (модель, усилие, доступ, скорость)

- **Анатомия:** `[ведущая иконка 16: провайдер / gauge / shield / bolt] [подпись] [шеврон 12]`, gap `--space-6`.
  Разделитель «·» между иконкой провайдера и подписью убирается: сейчас его рисует правило `span + span::before`
  (видно на `repro/repro-current.png`).
- **Размер:** только `lg`: чип живёт в панели поля ввода. Паддинг `--space-8`, радиус `--radius-sm`.
- **Тона:** нейтральный (прозрачный, hover `--sunk`) и **danger** для доступа `full` (рамка `--fail-edge`,
  фон `--fail-soft`, текст `--fail`, иконка щита).
- **Состояния:** rest · hover · open (`aria-expanded="true"` → `--sunk` + `--ink`) · focus-visible · disabled ·
  pending (смена после хода: иконка часов, текст `--wait`).
- **Переполнение:** подпись `.truncate`; иконка и шеврон `flex: none`. Контейнерный запрос к полю
  (`composer-box < 600`): усилие и скорость показывают только иконку (значение — в `aria-label` и `title`),
  потолок модели становится 150, **доступ сохраняет текст** (не короче 12ch).

### 11.4 Pill — `.pill` («3 субагента», «в фоне · 2», фильтры сайдбара)

- **Анатомия:** `[иконка 14] подпись [счётчик?]`, радиус `--radius-full`, рамка `--line`, фон `--panel`.
- **Размеры:** `sm` — фильтры и метки, `md` — над полем ввода.
- **Состояния:** rest · hover (рамка `--line-strong`) · open (`aria-expanded`) · focus-visible · с индикатором:
  точка `--run` пульсирует, пока внутри кто-то работает.
- **Раскладка:** пилюля над полем — внутри `.column-block`, её левый край совпадает с краем рамки поля.
- **Переполнение:** подпись `.truncate`, потолок — 100 % колонки; число не обрезается никогда.

### 11.5 QueueItem — `.queue-item`

- **Анатомия:**
  `[ручка IconButton sm] [номер: mono, --text-xs] [содержимое: текст .truncate + вложения] [Изменить] [Отправить сейчас] [×]`.
  Ручка и номер — ведущая зона, содержимое — `flex: 1 1 0; min-width: 0`, три действия — `flex: none`.
- **Размеры:** все действия `sm`; паддинг `--space-4`; радиус `--radius-md`; рамка `1px dashed var(--line)` — реплика
  ещё не отправлена. Высота строки при 14: 24 + 2 × 4 + 2 × 1 = **34** (box-sizing: border-box).
- **Состояния:** rest · hover (действия становятся `--ink`) · dragging (opacity .5, сплошная рамка) ·
  drop-target (полоса 2 px `--accent` сверху или снизу) · sending (спиннер вместо иконки «Отправить сейчас»,
  остальные действия disabled) · paused (над списком плашка `--fail-soft`) · editing (строка превращается в поле:
  сплошная рамка `--accent`, кнопки «Сохранить» primary sm и «Отмена» ghost sm, высота по содержимому, у тела
  `min-width: 0`) · orphan (номер «—» и подсказка).
- **Переполнение:** текст в одну строку с многоточием; полный текст — в `title` и в правке.
  `@container queue-item (max-width: 520px)`: «Изменить» и «Отправить сейчас» превращаются в IconButton sm
  (нужны иконки карандаша и самолётика; сейчас у «Изменить» иконки нет). При ширине меньше 320 «Изменить» уходит
  в меню «⋯». Вложения — одна строка чипов, остальные сворачиваются в «+N».

### 11.6 Composer — `.composer > .box`, `.draft-box`, `.temporary-box`

Сегодня полей ввода три, и у каждого свои числа: радиус 18 / 20 / 18, паддинг 12 / 13 / 12. Спецификация одна на все.

- **Анатомия:** `[полоса вложений?] [textarea] [панель: (настройки: SelectChip × 1–4 и «◔» сведений) (действия: 🎙⌄, +, Уточнить?, Стоп?, Отправить / В очередь)]`.
  Над полем — блоки колонки (пилюля, очередь, плашки); под ним — `access-strip`, ошибка отправки, состояние диктовки
  («запись · до 2 минут», «распознаётся»). Все они подчиняются §7.
- **Размеры:** радиус `--radius-xl`, паддинг `--composer-pad`, между textarea и панелью `--space-8`;
  textarea от 78 до `--composer-input-max`, кегль `--text-lg`; все контролы панели — `lg`.
- **Состояния:** rest · focus-within · drag-over (outline 2 px `--accent`, offset −2) · busy (появляются «Стоп» и,
  у Codex, «Уточнить»; «Отправить» становится «В очередь») · needs-you (плейсхолдер про Inbox) · disabled ·
  access-full (рамка `--fail-edge`, фокус `--fail`) · resized (ручка сверху, высота пользователя) · recording /
  transcribing (кнопка микрофона `--fail`, строка состояния над действиями) · без проекта (черновик: выбор проекта
  в заголовке).
- **Переполнение:** панель состоит из двух групп, каждая неделима (`flex-wrap: nowrap`). Порядок сдачи места:
  обрезается подпись модели → скрываются подписи усилия и скорости → «Уточнить сейчас» становится IconButton →
  группа действий целиком переносится под настройки (`composer-box < 420`). «◔» входит в группу настроек
  и отдельно не переносится. Сейчас на колонке 620 px он один уезжает во вторую строку, а на 430 и 320 панель
  вылезает за рамку на 91 и 201 px (`AUDIT.md`, §1).

### 11.7 Message — `.it`

- **Анатомия:** `[gut: кто · время · копировать] [body]`. Варианты: `it-user` (пузырь справа), `it-model`
  (без фона, на всю колонку), `it-tool` (свёрнутая строка инструмента), `it-perm` (карточка разрешения),
  `it-notice`, `it-agent` (карточка субагента).
- **Размеры:** реплики — `--text-lg / --leading-body`; gut — `--text-xs`; копирование — IconButton sm;
  пузырь человека: радиус `--radius-xl` с хвостом `--radius-xs` в правом нижнем углу, паддинг 12 / 16,
  `max-width: 87%` (94 % в узкой колонке); между репликами `--gap-stack`.
- **Состояния:** rest · hover/focus-within (видны время и копирование) · flash (переход по метке) ·
  streaming · error (`tool-error-preview`) · resolved permission (свёрнутый diff).
- **Переполнение:** у `body` — `min-width: 0` и `container: chat-body`; длинные слова — `overflow-wrap: anywhere`;
  код и таблицы прокручиваются по горизонтали **внутри себя**, а лента — никогда. Картинки раскладываются
  по контейнерному запросу `chat-body`.

### 11.8 StatusDot — `.status-dot` (единый индикатор работы и состояния)

Повод: во вкладке агента горела точка цвета провайдера (зелёная) вместо синей мигающей точки «работает».
Причина того же класса, что и у остальных багов: индикаторов шесть, и у каждого своя реализация.
`.chip .dot` (6 px, мигает и при `run`, и при `wait`), `.row-live-dot` (5 px, цвет через `currentColor`),
`.subagent-state` (символ «●» кеглем 8 px, размер зависит от шрифта), `.health-dot`, `.rail-wait`,
`.chat-row-status.t-run` (текст, сжатый до точки через `font-size: 0`). Точка с `background: currentColor`
наследует цвет родителя. Если тон не проставлен, она берёт цвет иконки провайдера.

- **Анатомия:** `<span class="status-dot" data-state="…">` — CSS-круг, не символ. Цвет задаёт **только**
  `data-state` через таблицу ниже; `currentColor` и наследование цвета запрещены.
- **Состояния и токены:**

  | `data-state` | Смысл | Цвет | Вид | Подпись (`aria-label` / `title`) |
  |---|---|---|---|---|
  | `run` | агент работает | `--run` | сплошная, **мигает** | «Работает» |
  | `wait` | ждёт человека (разрешение, вопрос) | `--wait` | сплошная, статичная | «Ждёт ответа» |
  | `fail` | ход упал | `--fail` | сплошная, статичная | «Ошибка» |
  | `ok` | ход завершён | `--ok` | сплошная, статичная | «Готово» |
  | `queued` | есть реплики в очереди, ход не идёт | `--queued` | кольцо 1.5 px без заливки | «В очереди» |
  | `idle` | не активен, остановлен пользователем | — | не рисуется (в выровненных списках — пустое место того же размера) | «Не активен» |

  Мигает только `run`: одна анимация — одно значение. Внимание к `wait` дают цвет, место в списке
  («Ждут» наверху) и текст, а не второе мигание. Так `.chip.tone-wait .dot`, который мигает сейчас, становится
  статичным. Сопоставление из модели: тон агента (`sv.tone`) берётся как есть; `ItemState` субагента и инструмента:
  `running → run`, `ok → ok`, `error → fail`, `stopped → idle` (остановка — не ошибка).
- **Провайдер не кодируется точкой.** Принадлежность Claude, Codex или zcode показывает только `ProviderIcon`.
  Цвета `--prov-*` точке недоступны: в правиле `.status-dot` нет ни одного `--prov-*`, это проверяет храповик.
- **Размеры:** `--dot-size` 6 px. Два варианта размещения:
  `inline` — в строке рядом с текстом (вкладка, чип, строка Inbox), `align-self: center`, отступ `--space-6`;
  `badge` — поверх иконки 16–17 px в правом нижнем углу, с кольцом `--dot-ring` 2 px цвета подложки
  (`box-shadow: 0 0 0 var(--dot-ring) var(--dot-surface)`, `--dot-surface` берёт родитель: `--sidebar`, `--panel`).
- **Анимация:** keyframes `status-pulse`, opacity 1 → .3 → 1, `--dur-pulse` 1.4 s, ease-in-out, бесконечно. Точки
  `run` на экране мигают синхронно: `animation-delay` берётся от общего времени, чтобы сайдбар не рябил.
- **Reduced motion** (`prefers-reduced-motion: reduce`): анимации нет, но `run` по-прежнему отличается от
  остальных без движения — сплошная точка с ореолом `0 0 0 2px var(--run-soft)` (в `badge` ореол заменяет кольцо подложки).
- **Доступность:** точка не бывает единственным носителем смысла (§2). Если рядом есть видимый текст состояния —
  `aria-hidden="true"`. Если нет (вкладка, строка сайдбара) — `role="img"` и `aria-label` с подписью из таблицы,
  тот же текст в `title`. Смену состояния объявляет владелец (строка фазы, `aria-live` строки), а не точка:
  иначе диктор зачитывает каждую вкладку. Контраст цвета точки с подложкой — не ниже 3 : 1 (WCAG 1.4.11): у всех
  пяти тонов на `ground`, `panel`, `sunk` и `sidebar` в обеих темах он не ниже 4.75 : 1 (минимум — `queued` на `sunk`).
- **Где какие состояния видны:** строка сайдбара, вкладка субагента и рейка «Фокуса» показывают только `run`,
  `wait`, `fail` — спокойные состояния скрыты, чтобы не шуметь. Чипы состояния, карточки субагентов и Inbox
  показывают все.
- **Переполнение:** `flex: none`, никогда не сжимается и не обрезается; в зоне «не сжимается» по §8.
- **Заменяет:** `.chip .dot`, `.row-live-dot`, `.subagent-state`, `.health-dot`, `.rail-wait` и трюк
  `.chat-row-status.t-run { font-size: 0 }`.
- **Проверка (e2e):** у агента в `run` при каждом провайдере (claude, codex, zcode) вычисленный `background-color`
  точки во вкладке, строке сайдбара и чипе равен `--run`, а `animation-name` — `status-pulse`; у прочих состояний
  анимации нет; при `reducedMotion: 'reduce'` анимации нет ни у одной точки, а у `run` есть ореол.

## 12. Охрана: чтобы класс ошибок не вернулся

1. **e2e-инвариант колонки** (`shell/test/e2e/layout.test.ts`) на настоящих компонентах, а не на `repro/`.
   Матрица: ширина колонки 320 / 430 / 600 ± 1 / 620 / 900 (через ширину окна, сайдбар и Inbox); шрифт 12 / 14 / 20;
   темы светлая и тёмная, включая явную тему **против** системной; режимы «Обычный», «Расширенный», «Фокус»,
   открытые файлы. Данные: длинная реплика в очереди, реплика в правке, три субагента, `full`, вложения, запись
   диктовки, Codex с «Уточнить». Проверки:
   - `|left(блок) − left(.composer .box)| ≤ 0.5` и то же для `right` у каждого `.column-block`
     (у ленты допуск — ширина полосы прокрутки);
   - `scrollWidth ≤ clientWidth` у каждой `.queue-item`, панели поля ввода и строк сайдбара;
   - у контролов в ряду одна высота;
   - `button.contains(document.elementFromPoint(центр))` для каждой кнопки очереди и панели: ничто не перекрыто
     (попадание в SVG внутри кнопки засчитывается);
   - у каждого контрола в фокусе контур виден и не обрезан родителем.
2. **Храповик** `scripts/check-css-tokens.mjs` (без зависимостей, в `npm test`). Разбирает объявления и ищет литералы
   цвета, `font-size` в px, `border-radius`, `z-index`, высот контролов, а также `outline: none` без замены.
   Каждое найденное сравнивается со **списком разрешённых по месту** — `файл · селектор · свойство · значение · №`
   (порядковый номер различает повторы одного свойства в одном селекторе) в `scripts/css-token-allowlist.json`. Новое место валит тест, даже если где-то другое удалили. Записи из списка только
   удаляются.
3. **Цвета — по отрисованному результату**, а не по вычисленному `--ink`: снимок пикселей ключевых элементов
   и `getComputedStyle(...).color` у нативных контролов в обеих темах.

## 13. Миграция: маленькие PR

Каждый PR — отдельная ветка, зелёный локальный CI (`npm test` + e2e) и снимки до и после в описании.
**Правило владения:** PR, который переводит компонент, переносит его правила из `styles.css`, блока «редизайн A»
и `workspace.css` в файл компонента и **в том же PR удаляет** перекрытые старые правила. Отдельного финального
«большого схлопывания» нет.

| PR | Что | Видимые изменения | Риск и проверка |
|---|---|---|---|
| **1. ## 14. Как пересобрать `repro/`

`repro/` — статичная копия колонки беседы на настоящем CSS из `ui/src` (13 файлов в порядке приложения). Это
иллюстрация, а не тест. В ней нет шрифтов `@font-face`, полосы прокрутки ленты, ресайза и вложений.
Доказательство даёт только e2e из §12.1.

```
python3 -I design/2026-11-06-design-system/repro/build.py
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --allow-file-access-from-files \
  --window-size=1280,2300 --screenshot=repro-current.png "file://$PWD/design/2026-11-06-design-system/repro/repro-current.html"
```

Замеры выводятся в `<pre class="metrics">` под каждой колонкой и в `body[data-metrics]` (`--dump-dom`).
